# 작성·리뷰·적용 연결 관측

2026-09-20, 임시 Git 저장소의 재시도 함수 변경을 문서에 반영했다. 별도 작성 에이전트가 결정을 만들고 다른 에이전트가 독립 리뷰했으며, 실행 에이전트가 CLI로 문서를 적용했다. [원본과 실제 응답](../../../../tests/knowledge/workflow-observation/README.md)을 보존했다.

## 입력과 결과

독자는 재시도 함수를 호출하는 BE 개발자이며, 목적은 재시도 횟수와 호출자에게 전달되는 예외를 판단하는 것이다. 코드에서 최대 시도 횟수를 3회에서 4회로 늘리고, 별도 버전 문자열 함수를 추가했다. 기존 문서는 최초 요청 외 최대 두 번 재시도와 권한 오류·마지막 연결 오류의 전달을 설명했다.

작성자는 재시도 문장만 “최초 요청 외에 최대 세 번 더 시도한다”로 수정했다. 권한 오류와 마지막 연결 오류의 전달은 유지했고, 추가된 버전 문자열 함수는 이 문서의 계약을 바꾸지 않는다는 이유를 남겼다. 리뷰어는 변경 전후 소스와 완성 문서 전체를 읽고 네 항목을 모두 통과로 판정했다.

그 실제 리뷰를 연결해 적용한 문서는 수정안과 일치했다. 동일 입력으로 재실행했을 때 완료 ID도 같았다.

| 기록 | ID |
|---|---|
| 검토 자료 묶음 | `56102f71ec0a9fa76facd095ee8a40d6410b5878e6f44669bd2ad9928065d07a` |
| 수정안 | `1e4172bfdc60c4527dfbad0881a32ca71eb1cdc5f8dc19b59043a1505771e297` |
| 완료 | `f2546dd1f60fda1bf9f09a2127015d6092f4cc75396d9066363535d6bd4995da` |

## 관측의 한계

에이전트 생성 한도 때문에 기존 작성·판정 에이전트를 재사용했다. 새 사례의 원본과 관련 지침만 전달하고 기대 답안이나 원하는 판정은 제공하지 않았지만, 완전히 새 맥락의 실행을 입증한 것은 아니다. 스킬의 해당 지침을 텍스트로 전달했으며, 설치된 스킬의 자동 발견·선택도 검증하지 않았다.

리뷰어는 제공된 텍스트만 검토했고 해시·Git 상태·실행 결과는 직접 검증하지 않았다고 명시했다. 원본 대조와 적용 결과 확인은 실행 에이전트가 수행했다. 역할별 파일 접근을 차단했던 하네스 제약을 우회해서 실행한 것으로 기록하지 않는다.

모델을 다시 호출하는 평가 플랫폼은 만들지 않았다. 회귀 검사는 기록된 작성·리뷰 응답을 그대로 사용해 Git 이력을 복원하고, 수정안과 완료 결과를 재현한다. 한 사례의 성공은 다른 문서나 모델의 판단 품질, 장시간 무인 실행의 신뢰성을 보장하지 않는다.
