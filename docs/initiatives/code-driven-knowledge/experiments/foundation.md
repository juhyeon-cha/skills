# 1단계 보완 구현과 조건별 판정

1단계의 접수·분류·인계, 실행 종료·격리와 전환, 문서 평가 계약을 구현했다. 코드→문서의 실제 독립 반려·수정·적용 중단·재개·다음 변경을 관측했다. **전체 단계 완료는 보류한다. 새 일반 에이전트의 CLI 인계가 하네스 역할 미식별로 실행 전에 차단됐다.** 별도 프로세스의 재개 성공과 이 미실행을 합쳐 통과로 처리하지 않는다.

시작 기준은 fetch로 확인한 origin/main `96845197702771ae969b75263f64e228d08f8be3`이며 `9e59feb`을 포함한다. 메인 체크아웃은 수정하지 않고 할당된 linked worktree의 `codex/knowledge-foundation`에서 작업했다. 기존 사용자 변경은 없었다. 원격 쓰기·릴리스·외부 원장 변경은 수행하지 않았다.

## 확인한 증거

- [설치 연속 실행](../../../../tests/knowledge/foundation-observation/README.md): 실제 명령·응답, 세 리뷰 JSON과 패킷, B/C 완료·문서, 고정 Git 이력. 첫 반려는 성공 조기 반환과 ConnectionError 조건, 오류 전달 예외 누락을 검출했다. 수정안은 새 패킷으로 통과했다.
- [최종 패키지 재실행](../../../../tests/knowledge/foundation-observation/final-replay-3/result.json): 현재 소스를 복사해 실행하고 설치 파일 hash를 남겼다. 패킷 전체가 실제 독립 리뷰 입력과 같음을 확인한 뒤 저장 응답을 사용했다. 새 모델 호출이라고 기록하지 않았다.
- [문서 평가](../../../../tests/knowledge/foundation-evaluation/README.md): 정상·변형의 실제 입력/응답, 고정 기준/권위, 독립 판정. 내용 검토와 독자 증거 결과가 각각 있다. 목표 코드 없음은 허용하며, 잘못된 완료 주장은 실패한다. 표현 비교로 코드 작업 없이 문서 설명을 종료할 근거를 얻었다.
- [코드 리뷰](../../../../tests/knowledge/foundation-observation/code-review.md): 상태 무시와 retire/intake 경쟁 조건을 발견해 수정. 실제 파일·검사는 부모가 확인했고 재검토는 전달된 변경 내용에 한정했다.

## 실패·미실행·사용자 개입

기본 Python에는 jsonschema가 없어 의존성 확인이 실패했다. 이미 설치돼 있던 `/private/tmp/knowledge-contract-venv`의 Python 3.14.7·jsonschema 4.26.0을 사용했으며 새 의존성 다운로드는 없었다.

하위 에이전트의 쓰기, 일부 실행, 보조 에이전트의 독자 spawn은 `GUARD-DENY: UNREACHED — child role is unidentified`로 차단됐다. 부모가 반환된 초안을 기록하고 독자를 직접 호출했으며, 독립 판정자가 실행하지 못한 hash 검사는 부모가 수행했다. 새 인계 에이전트는 스킬 파일 읽기까지만 성공했다. 이 실패를 새 일반 에이전트 실행 지원으로 바꾸지 않았다. 사용자에게 정책 재승인이나 원격 권한을 요구하지 않았고 하네스 설정도 바꾸지 않았다.

형식 검사는 내용 통과의 근거가 아니다. 실제 독자의 정직한 정보 부족 답변도 필수 문서 정보 누락을 상쇄하지 않는다. 목표 품질 통과는 3단계 구현 완료나 배포 확인이 아니다.

## 검증 명령과 경계

- `KNOWLEDGE_PYTHON=/private/tmp/knowledge-contract-venv/bin/python bash tests/knowledge/source-contract-check.sh`: 원본·영향·적용·리뷰·프로젝트·접수 총 48개 회귀 통과.
- `bash tests/knowledge/document-ac-check.sh`: 기존 문서 평가 7개 회귀.
- `KNOWLEDGE_PYTHON=/private/tmp/knowledge-contract-venv/bin/python bash tests/knowledge/foundation-check.sh`: 고정 입력 형식 검사와 최종 설치 통합 재실행. 내용 판정은 저장된 실제 독립 응답에 근거.
- `bash scripts/check.sh`: marketplace/plugin validate, shellcheck, 설명 3중 일치.
- `git diff --check`: 공백 오류 검사.

전체 `tests/run-all.sh`는 실행하지 않았다. 변경한 toolkit 경로와 지식 갱신/평가 검사 및 저장소 필수 게이트를 수행했다. 러너의 원장·호스트 의존 검사나 다른 플러그인 코어 검사는 이번 결과로 통과를 주장하지 않는다.
