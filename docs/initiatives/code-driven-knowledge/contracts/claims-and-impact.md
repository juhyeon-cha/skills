# 주장·근거 연결과 갱신 후보 추출

코드 변경 후 검토할 문서를 찾는 개발용 CLI를 구현했다. 문서의 실제 문장과 고정 Git snapshot의 파일을 연결하면, 변경된 파일을 근거로 삼은 문서·주장과 변경 이유를 출력한다. 이 결과는 검토 후보이며, 문장이 틀렸다는 판정이나 문서 수정 결과는 아니다.

## 호출자가 준비할 것

작성 에이전트가 문서의 주장마다 식별자, 문서에 그대로 존재하는 문장, 근거 파일 경로를 지정한다. CLI의 `bind`는 문장 존재 여부와 근거 파일 존재 여부를 검사하고, 기준 snapshot ID와 문서 전체 내용의 SHA-256을 저장한다. 같은 문서 안에서 식별자가 중복되거나 근거가 없으면 실패한다.

문서 경로는 지정한 문서 루트 기준이고, 근거 경로는 소스 저장소 루트 기준이다. 문서 루트 아래의 심볼릭 링크와 상위 경로 참조는 거부한다. [실행 절차와 입력 예시](../../../../tests/knowledge/source-contract/README.md#bind-claims-and-find-affected-documents), [자료 스키마](../../../../tests/knowledge/source-contract/impact-schema.json)를 제공한다.

`impact`는 이전·이후 snapshot을 Git 원본과 다시 대조하고, 연결 자료의 기준 및 현재 문서 내용을 확인한 뒤 변경을 계산한다. 문서 수정·삭제, 다른 기준 snapshot, 변조된 원본은 출력 생성 전에 실패한다. 정상적으로 문서를 고쳤다면 연결의 타당성을 검토한 뒤 다시 `bind`해야 한다.

## 결과를 읽는 기준

| 입력 상태 | 결과와 후속 행동 |
|---|---|
| 연결된 파일의 수정·삭제·모드 변경 | 해당 파일을 근거로 한 모든 주장을 검토 후보로 출력한다 |
| 이름 변경 후보 | 기존 경로를 참조한 주장을 후보로 출력한다. 근거 경로를 자동 교체하지 않는다 |
| 여러 문서가 같은 파일을 참조 | 각 문서의 관련 주장을 모두 출력한다 |
| 추가 파일 또는 연결 없는 파일 변경 | `unlinked_changes`에 남긴다. 에이전트가 새 연결 필요성을 판단한다 |
| 원본 변경 없음 | 후보와 미연결 변경이 모두 빈 목록이다 |
| 문서나 연결의 기준이 달라짐 | 실패한다. 오래된 연결을 사용해 후보 없음을 보고하지 않는다 |

파일 전체가 근거 단위이므로 무관한 줄의 수정도 후보를 만들 수 있다. 반대로 선언되지 않은 호출 관계나 정책 영향은 찾지 못한다. 따라서 후보 목록만 비어 있다고 영향 없음으로 판단해서는 안 된다. 문장이 코드에서 성립하는지와 연결이 충분한지는 에이전트가 판단할 책임으로 남는다.

## 검증과 다음 단계

임시 Git 저장소를 사용하는 테스트로 수정·삭제·이름 변경 후보, 공유 근거, 새 파일·미연결 변경, 무변경, 반복 결과, 기존 출력 보존을 확인한다. 오래된 문서·기준, 원본 파일 누락, 없는 문장·근거, 중복 식별자, 위험 경로와 심볼릭 링크도 실패 사례로 검사한다. 실행 명령은 기존 `source-contract-check.sh`에 연결했다.

2026-09-20 검증에서 기존 원본 계약 테스트 10개와 신규 연결·영향 테스트 6개가 통과했다. 입력 순서 변경 후 동일 결과, bind/impact 실행 전후 문서 내용과 Git HEAD·작업 상태 보존도 확인했다. 저장소 필수 게이트는 통과했고 전체 개발 테스트 묶음은 실행하지 않았다. 독립 정적 리뷰에서는 기능 결함이 없었으며 테스트 중복 수집 지적을 수정했다. 리뷰 에이전트의 실행은 하네스 훅에 차단되어 테스트 실행 결과는 구현 세션에서 확보했다.

이 단계는 원본이나 문서를 수정하지 않는다. 자료를 읽는 동안의 동시 편집을 잠그지 않으며, 현재 브랜치 최신성도 보장하지 않는다. 후속 [문서 수정 계약](document-updates.md)에서 에이전트의 유지·수정·삭제 결정을 검증하고, 기준 문서가 그대로일 때 수정안을 적용하는 흐름을 구현했다. Promptfoo와 LLM 응답 평가는 계속 보류한다.
