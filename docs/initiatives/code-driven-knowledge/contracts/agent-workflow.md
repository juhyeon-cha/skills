# 에이전트 작성·리뷰와 CLI 실행 연결

근거 수집부터 문서 적용까지를 저장소 개발용 스킬과 CLI로 연결했다. 사용자는 갱신할 저장소·변경 범위·문서 목적을 지정하고, 에이전트가 근거 판단과 문장 작성, 독립 리뷰, 로컬 적용을 진행한다. 누락된 정책 결정이나 근거 충돌만 사용자에게 돌아오도록 절차를 정했다.

이번에 추가한 스킬은 설치본에 배포하지 않았다. `.claude/skills/`의 개발용 절차를 명시적으로 읽어 사용하는 단계이며, 설치 후 자동 선택이나 다른 실행 환경에서의 로딩은 아직 검증하지 않았다.

| 구성 요소 | 책임 |
|---|---|
| [refresh-knowledge](../../../../.claude/skills/refresh-knowledge/SKILL.md) | 입력 확보, 수집·영향 분석 실행, 근거별 결정, 작성·리뷰 위임, 통과 후 적용과 재개 |
| 기존 [writing-for-humans](../../../../plugins/toolkit/skills/writing-for-humans/SKILL.md) | 독자와 목적에 맞는 수정 문장 작성 |
| [review-knowledge](../../../../.claude/skills/review-knowledge/SKILL.md) | 원본 일치, 결정 누락, 독자의 행동 가능성, 불확실성 표현을 독립 리뷰 |
| [workflow.py](../../../../tests/knowledge/source-contract/workflow.py) | 검토 자료 묶음 생성, 리뷰가 검토한 수정안과 같은지 검사, 조건부 적용 후 완료 기록 생성 |

## 리뷰 이후의 변경을 탐지한다

검토 자료 묶음에는 수정안 전체, 변경 전후 소스, 기존 근거 연결, 독자와 목적이 들어간다. 리뷰 결과는 이 묶음 ID와 수정안 ID를 모두 참조한다. 문서가 맞다는 단일 표시 대신 네 검토 항목의 결과와 지적 사항을 남긴다.

`finish`는 리뷰 누락·다른 수정안의 리뷰·미검증 항목·남은 지적 사항이 있으면 문서를 바꾸기 전에 실패한다. 수정안 또는 독자 맥락이 달라지면 새 묶음을 생성하고 다시 리뷰한다. 통과하면 기존 조건부 적용을 실행하고, 문서 결과 확인 뒤 다음 근거 연결을 포함한 완료 기록을 저장한다.

완료 기록이 이미 있어도 현재 문서와 근거를 다시 검증한다. 적용 후 완료 기록 저장만 실패했다면 같은 입력으로 재개할 수 있다. 부분 적용·동시 편집 제한은 [문서 수정 계약](document-updates.md)을 따른다.

리뷰 JSON은 서명이 아니다. CLI는 실제 독립 에이전트가 작성했는지 인증하지 못하므로 실행 에이전트가 독립 리뷰 응답을 확보하고 그대로 보존해야 한다. 기존 저수준 `update.py apply`는 남아 있으며, 이번 스킬은 리뷰 연결을 확인하는 `workflow.py finish`를 사용한다. 모든 문서 수정 수단을 강제로 통제하는 보안 경계는 아니다.

## 확인한 범위

[재시도 문서 갱신 사례](../experiments/agent-refresh.md)에서 별도 작성자와 리뷰어의 실제 응답을 받아 수집→작성→리뷰→적용→재실행을 확인했다. 기록된 원본 Git 이력과 응답으로 동일한 완료 결과를 재현하는 회귀 검사도 추가했다.

기존 계약 검사와 신규 리뷰 연결·관측 재현 검사를 합쳐 33개 테스트가 통과했다. 두 스킬의 형식 검사와 저장소 필수 게이트도 통과했다. 별도 코드 리뷰는 전달된 코드의 정적 검토 범위에서 결함을 찾지 못했다. 저장소 전체 개발 테스트 묶음은 실행하지 않았다.

전체가 백그라운드에서 무인 실행되는 것은 아니다. 현재 실행 에이전트가 CLI 호출과 에이전트 간 전달을 담당한다. 새 주장·새 문서 생성, 여러 저장소, 원격 게시, 설치 배포, 일반적인 문서 정확성은 미검증 범위다. Promptfoo와 LLM 응답 평가 도입은 계속 보류한다.
