# 에이전트 작성·리뷰와 CLI 실행 연결

근거 수집부터 문서 적용까지를 toolkit 설치 스킬과 프로젝트 CLI로 연결했다. 사용자는 갱신할 저장소·변경 범위·문서 목적을 지정하고, 에이전트가 근거 판단과 문장 작성, 독립 리뷰, 로컬 적용을 진행한다. 누락된 정책 결정이나 근거 충돌만 사용자에게 돌아오도록 절차를 정했다.

두 스킬과 실행 코드는 toolkit 패키지 안에 있다. 각 스킬은 자체 참조 문서를 포함하며, 작성과 독립 리뷰는 스킬 이름으로 의존성을 명시한다. 공개 진입점은 `refresh-knowledge/scripts/knowledge.py`이며 [프로젝트 사용법](../../../../plugins/toolkit/skills/refresh-knowledge/references/project.md)을 따른다. 원격 릴리스 발행은 별도다.

| 구성 요소 | 책임 |
|---|---|
| [refresh-knowledge](../../../../plugins/toolkit/skills/refresh-knowledge/SKILL.md) | 입력 확보, 수집·영향 분석 실행, 근거별 결정, 작성·리뷰 위임, 통과 후 적용과 재개 |
| 기존 [writing-for-humans](../../../../plugins/toolkit/skills/writing-for-humans/SKILL.md) | 독자와 목적에 맞는 수정 문장 작성 |
| [review-knowledge](../../../../plugins/toolkit/skills/review-knowledge/SKILL.md) | 원본 일치, 결정 누락, 독자의 행동 가능성, 불확실성 표현을 독립 리뷰 |
| [workflow.py](../../../../plugins/toolkit/skills/refresh-knowledge/scripts/workflow.py) | 검토 자료 묶음 생성, 리뷰가 검토한 수정안과 같은지 검사, 조건부 적용 후 완료 기록 생성 |

## 리뷰 이후의 변경을 탐지한다

검토 자료 묶음에는 수정안 전체, 변경 전후 소스, 기존 근거 연결, 독자와 목적이 들어간다. 리뷰 결과는 이 묶음 ID와 수정안 ID를 모두 참조한다. 문서가 맞다는 단일 표시 대신 네 검토 항목의 결과와 지적 사항을 남긴다.

`finish`는 리뷰 누락·다른 수정안의 리뷰·미검증 항목·남은 지적 사항이 있으면 문서를 바꾸기 전에 실패한다. 수정안 또는 독자 맥락이 달라지면 새 묶음을 생성하고 다시 리뷰한다. 통과하면 기존 조건부 적용을 실행하고, 문서 결과 확인 뒤 다음 근거 연결을 포함한 완료 기록을 저장한다.

완료 기록이 이미 있어도 현재 문서와 근거를 다시 검증한다. 적용 후 완료 기록 저장만 실패했다면 같은 입력으로 재개할 수 있다. 부분 적용·동시 편집 제한은 [문서 수정 계약](document-updates.md)을 따른다.

리뷰 JSON은 서명이 아니다. CLI는 실제 독립 에이전트가 작성했는지 인증하지 못하므로 실행 에이전트가 독립 리뷰 응답을 확보하고 그대로 보존해야 한다. 기존 저수준 `update.py apply`는 남아 있으며, 이번 스킬은 공개 `review`·`resume` 명령에서 리뷰 연결을 확인하는 내부 `workflow.py finish`를 사용한다. 모든 문서 수정 수단을 강제로 통제하는 보안 경계는 아니다.

## 반복 실행과 복구

프로젝트의 SQLite 파일은 설정, 현재 기준과 근거 연결, 실행별 상태를 저장한다. JSON 파일은 에이전트에게 전달할 검토 자료와 결과다. `start`는 같은 활성 변경에 같은 실행 ID를 반환하고 다른 변경은 기존 실행 해결 전까지 거부한다. `status`와 `resume`에는 프로젝트 위치와 실행 ID만 필요하다.

`resume`은 적용 중 상태를 먼저 저장한다. 파일 반영 후 프로세스가 종료되어도 같은 실행으로 재개하고, 결과 검증 후 기준·근거 연결·완료 상태를 한 트랜잭션으로 확정한다. 다음 `start`는 이 기준을 자동 사용한다. 같은 프로젝트의 동시 쓰기는 거부한다. 여러 프로젝트에서 같은 문서를 편집하는 경우까지 잠그지는 않는다.

현재 기준의 완료 실행을 재확인하면 문서 변조도 검사한다. 더 최신 기준이 있으면 과거 실행은 이력으로 반환하며 문서를 되돌리지 않는다. 설정 변경이나 DB 마이그레이션은 지원하지 않는다.

## 확인한 범위

[설치 패키지 실행 관측](../experiments/installed-workflow.md)은 별도 세션이 실제 설치 파일을 읽고 작성·독립 리뷰·적용한 결과다. 연속 두 변경, 프로세스 종료 후 재개, 동시 쓰기, 검토 자료 변조는 복사한 패키지를 사용하는 자동 검사로 확인한다. 상세 완료 기준은 [K1–K5](../acceptance.md)를 따른다.

실행 에이전트가 CLI 호출과 에이전트 간 전달을 담당한다. 백그라운드 스케줄러, 새 주장·새 문서 생성, 여러 저장소, 원격 게시와 일반적인 문서 정확성은 이 검증으로 보장하지 않는다. Promptfoo 도입은 보류한다.
