# 문서 수정안 준비와 조건부 적용

갱신 후보를 유지·수정·삭제 결정으로 바꾸고, 문서 기준이 그대로일 때 적용하는 개발용 CLI를 구현했다. 에이전트가 코드 근거를 읽고 결정을 작성하며, CLI는 결정 누락과 자료 불일치를 검사하고 문서를 반영한다. 모델 응답 평가나 자동 의미 판정은 추가하지 않았다.

## 입력에서 결과까지

1. 에이전트는 후보 주장마다 결정과 이유를 작성한다. 수정 문구는 `writing-for-humans`로 독자의 용도에 맞추고, 변경 후 코드 근거를 지정한다. 연결되지 않은 변경에도 문서 수정이 필요 없다는 명시적 결정과 이유가 필요하다.
2. `prepare`는 모든 후보에 결정이 있는지, 근거 파일이 변경 후 snapshot에 존재하는지, 문서 원문이 기준과 일치하는지 확인한다. 수정 전후 전체 문장과 내용 해시, 다음 근거 연결 자료를 담은 계획을 새 파일에 저장한다. 원본 문서는 바꾸지 않는다.
3. 수정안의 의미와 문맥을 리뷰한 뒤 `apply`로 적용한다. CLI는 계획을 재계산하고 전체 문서를 사전 검사한다. 기준 원문 또는 이미 적용된 목표 내용과 다른 문서는 덮어쓰지 않는다.
4. 모든 문서가 목표 내용과 일치할 때만 성공을 출력한다. 그때 계획의 `next_bindings`를 다음 갱신의 근거 연결로 사용한다.

[입력 예시와 실행·복구 절차](../../../../tests/knowledge/source-contract/UPDATES.md), [자료 스키마](../../../../tests/knowledge/source-contract/update-schema.json)를 제공한다. 이 CLI는 저장소 개발용이며 설치 스킬에 배포하지 않았다.

## 결정별 동작

| 결정 | 허용하는 변화 | 실패하는 경우 |
|---|---|---|
| 유지 | 문장은 그대로 두고 변경 후 근거를 확인한다. 이름이 바뀐 근거 경로를 갱신할 수 있다 | 문장이 달라지거나 변경 후 근거가 없음 |
| 수정 | 원문 발췌를 새 문장으로 교체한다 | 발췌가 여러 곳에 있거나 다른 수정과 겹침, 빈 문장, 근거 없음 |
| 삭제 | 원문 발췌와 해당 근거 연결을 제거한다. 파일과 주변 형식은 보존한다 | 삭제 결정에 새 문장이나 근거를 함께 지정함 |
| 미연결 변경은 문서 수정 불필요 | 해당 결정을 계획에 기록한다 | 결정 누락, 중복, 이유 없음, 나중에 처리한다는 다른 동작 지정 |

새 주장·새 문서 작성은 아직 지원하지 않는다. 미연결 변경이 문서 수정을 요구한다면 별도로 해결해야 하며, 단순히 수정 불필요로 표시해서는 안 된다. 문장 존재와 근거 경로가 유효하다는 검사는 내용의 진실성을 증명하지 않는다.

모든 주장이 제거된 문서는 다음 연결 자료에서 빠진다. 남은 주장이 전혀 없으면 `next_bindings`는 `null`이다. 이는 추적 대상이 없다는 뜻이며 지식 갱신 전체가 완성됐다는 뜻은 아니다.

## 실패와 재개

실행 전부터 문서 충돌이 있으면 아무 문서도 바꾸지 않는다. 적용은 파일별 임시 파일 교체 방식이므로 두 번째 파일에서 실패하면 첫 번째 파일만 반영된 상태가 남을 수 있다. 같은 계획으로 재실행하면 목표 내용이 이미 반영된 파일을 건너뛰고 나머지를 처리한다. 중간에 작성된 다른 내용은 보존하고 실패한다. 부분 실패에서 이전 근거 연결을 다음 것으로 전환하지 않는다.

이 방식은 다른 작성자가 없는 전용 작업 폴더에서 사용한다. 다중 파일 전체의 원자성, 임의의 동시 편집자와의 경쟁 방지, 시스템 장애 후 디스크 영속성을 보장하지 않는다. 파일 권한 비트는 보존하지만 소유권·ACL·확장 속성 보존은 범위 밖이므로 일반 작업 문서에 한정한다.

## 검증 경계

임시 Git 이력과 실제 CLI로 원본 수집부터 후보 추출, 수정안 준비, 적용, 다음 근거 연결을 사용한 무변경 확인까지 검사한다. 테스트에는 부분 실패 후 재개, 적용 후 독립 수정 보존, 원본 불일치·누락, 계획 변조, 심볼릭 링크, 결정 누락·중복, 모호한 수정, 모든 주장 제거를 포함한다. 실패 주입은 임시 문서에서만 수행한다.

2026-09-20 기준 기존 원본·영향 계약 테스트 16개와 신규 수정안·적용 테스트 11개, 총 27개가 통과했다. 저장소 필수 게이트도 통과했다. 저장소 전체 개발 테스트 묶음은 실행하지 않았다.

독립 리뷰는 하네스 훅이 자식 에이전트의 파일 접근을 차단하여 전달된 코드와 검증 설명을 대상으로 진행했다. 실제 실행 검증은 구현 세션에서 수행했다. 이 결과는 문서 의미의 자동 판단이나 운영 저장소에서의 무인 실행을 입증하지 않는다.
