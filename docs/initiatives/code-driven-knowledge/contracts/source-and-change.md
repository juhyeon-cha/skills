# 원본 근거와 변경분 계약 v1

다음 단계의 지식 갱신이 대화 기억이나 작업 디렉터리의 우연한 상태에 의존하지 않도록, 고정 Git 커밋에서 원본을 수집하고 파일 변경분을 비교하는 개발용 CLI를 구현했다. Promptfoo와 LLM 응답 평가 고도화는 전체 흐름 구현 이후로 미뤘다.

이번 범위는 **원본 수집·파일 변경 비교·자료 검증**이다. 문서 작성과 지식 반영, 의미 영향 판단은 아직 연결하지 않았다. 배포 스킬을 추가하지 않고 [개발용 CLI](../../../../tests/knowledge/source-contract/README.md)로 계약을 검증한다.

## 계약과 책임

[JSON Schema](../../../../tests/knowledge/source-contract/schema.json)가 자료 형태의 원본이다. 검증에는 `jsonschema==4.26.0`을 사용한다. 별도 가상환경에 설치하며 의존성이 없으면 검사를 생략하지 않고 실패한다.

| 자료 | 포함하는 것 | 확인하는 것 |
|---|---|---|
| snapshot | 저장소 식별자, 해석된 커밋 ID, 명시적 파일·디렉터리 범위, 파일 경로·모드·본문·SHA-256 | 스키마, 경로 범위, 중복, 파일 본문과 hash, 전체 자료 ID |
| change | 같은 저장소·범위의 이전/이후 snapshot ID, 추가·수정·삭제·이름 변경 후보 | 두 snapshot으로 변경 목록을 재계산해 결과와 비교 |

자료 ID는 자신의 ID 필드를 제외한 JSON을 정해진 직렬화 방식으로 SHA-256 계산한 값이다. 같은 커밋·저장소 식별자·범위라면 수집 결과가 바이트 단위로 같다. 현재 작업 파일의 미커밋 수정은 읽지 않는다. 실행 위치가 저장소 하위 디렉터리여도 경로 기준은 저장소 루트다.

파일 이름 변경은 삭제·추가 쌍의 본문 hash와 파일 모드가 정확히 같고 양쪽에서 유일할 때만 후보로 표시한다. 여러 파일이 같은 내용을 가지거나 이동과 수정이 함께 일어났다면 삭제·추가로 남는다. 후보가 같은 도메인 개념이라는 의미는 아니다.

## 검증 강도를 구분한다

`check`만 실행하면 스키마와 내부 hash의 일관성을 확인한다. 누군가 본문과 hash를 함께 다시 만든 자료의 진위를 증명하지 못한다. `check --repo`는 고정 커밋의 선택 범위를 다시 수집해 전체 자료를 비교하므로 파일 누락도 검출한다. change 검사는 이전·이후 자료를 반드시 함께 받고, `--repo`가 있으면 두 원본까지 대조한다.

저장소 식별자는 호출자가 지정하는 값이며 원격 서버의 신원을 인증하지 않는다. 빈 파일 집합은 범위 내 모든 파일이 삭제된 상태를 표현하기 위해 허용한다. 따라서 최초 범위를 지정할 때는 출력된 파일 수가 의도와 맞는지 확인해야 한다.

원본은 UTF-8 일반 파일과 실행 가능 파일 모드로 한정한다. 선택 범위 안의 심볼릭 링크·서브모듈·바이너리·UTF-8이 아닌 내용은 실패한다. 출력은 새 파일에만 기록하므로 기존 결과를 덮어쓰지 않는다. 중간 종료 때는 불완전한 새 출력이 남을 수 있어 새 경로로 재실행해야 한다.

## 검증 결과

- 실제 임시 Git 이력을 사용하는 회귀 테스트 10개로 고정 커밋·반복 결과, 미커밋 수정 무시, 추가·수정·삭제·이름 변경 후보, 모드 변경, 모호한 후보, 전체 삭제를 확인했다.
- 스키마 오류·본문 변조·파일 누락·변경 목록 변조·범위/저장소 불일치·존재하지 않는 근거·기존 출력 덮어쓰기·지원하지 않는 파일이 실패하는지 확인했다.
- 독립 정적 리뷰에서 저장소 하위 경로와 범위 밖 비 UTF-8 파일명 문제를 발견했다. 두 문제의 수정 전 실패를 재현하고 회귀 테스트로 수정 후 통과를 확인했다. 재검토의 추가 지적 사항은 없었다.
- SAP Harness `36a31860ae66c0d03b99ec244abe891a642dbdc4`의 `AiAnalysisTab.tsx`, `chat/model.ts`를 실제로 수집·원본 대조했다. 반복 snapshot ID는 `6d14a83a063ff417063f78f2074555f7d1e6e37c9a2be00e39b6c0d876b3a466`으로 같았다. 직전 커밋과 이 두 파일의 변경은 0개였다. 실제 소스의 무변경 경로를 확인한 것이며, 변경 종류 검증은 임시 Git 사례로 수행했다.

개발 검사는 `KNOWLEDGE_PYTHON=<가상환경 Python> bash tests/knowledge/source-contract-check.sh`로 실행한다. 저장소 전체 러너도 이 셸 파일을 자동 발견하며 같은 환경 변수가 필요하다. 모델 호출이나 SAP 실행은 하지 않는다.

## 다음 경계

이 자료만으로 심벌 관계·정책 영향·현재 브랜치의 최신성·안전한 다중 문서 반영을 보장하지 않는다. 후속 [주장·근거 연결 계약](claims-and-impact.md)에서 snapshot을 기준으로 문서의 주장과 파일 근거를 연결하고, 변경된 근거가 참조된 문서의 후보 목록을 구현했다. 다음은 의미 판단과 문서 수정 단계를 연결하는 것이다. 기술 실행 기록과 하네스의 업무 상태는 분리해서 관리한다.
