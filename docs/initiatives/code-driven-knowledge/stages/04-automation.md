# 4단계: 개발 흐름과 자동 연결

검증된 양방향 변경 흐름을 사용자 요청·개발 이벤트·정기 검사에 연결하고, 사람에게 실제 결정이 필요한 예외만 전달한다.

[전체 로드맵](../roadmap.md) · 단계 상태: 진행 중 — 로컬 자동화 구현·수용 관측 완료, 최종 독립 판정 전

## 진입 조건

3단계 양방향 반영·구현 검증 흐름이 검증돼야 한다. 대상 저장소·실행 계기·접근 권한·원격 반영 정책을 명시한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S4-01 | 실행 계기 | 사용자 요청·문서 변경·코드 PR·병합·정기 검사 중 지원 계기를 정의하고 입력 버전을 고정한다. 작성·리뷰·구현·검증의 필요한 경로를 선택한다. 초안과 반영 완료 상태를 구분한다. |
| S4-02 | 순서와 중복 | 이벤트 중복·지연·순서 역전·동시 실행을 처리한다. 같은 변경의 코드·문서 수정·PR 생성·게시 효과가 중복되지 않도록 한다. 자동 생성한 변경이 역방향 변경으로 다시 시작돼 무한 반복하지 않게 원인 실행을 연결한다. |
| S4-03 | 실패 운영 | 모델·네트워크·권한·외부 서비스 실패를 분류하고 재시도 가능 여부·중단 기준·재개 위치를 기록한다. 문서 반영 성공과 코드 구현·검증 성공을 따로 추적하고 성공하지 않은 단계나 외부 반영을 완료로 표시하지 않는다. |
| S4-04 | 사람 개입 | 자동 수정과 정책 결정을 구분한다. 필요한 질문에는 충돌 근거·영향·선택지를 포함하고 응답 후 해당 실행을 이어간다. 사용자 승인 경계를 이벤트 설정으로 우회하지 않는다. |
| S4-05 | 오래된 지식 검사 | 정기 검사로 누락된 이벤트, 기준 불일치, 원본 소실과 구현 대기 목표를 발견한다. 승인된 미구현 목표는 오래된 문서로 오판해 되돌리지 않는다. 미변경 상태는 불필요하게 재작성하거나 알리지 않는다. |
| S4-06 | 운영 관측 | 실행 시간·모델 호출·재시도·사용자 개입 사유를 측정한다. 성공·실패·대기 상태와 실제 산출물을 연결하고 운영자가 실행을 중단·재개할 수 있어야 한다. |

## 필수 판정 시나리오

허용된 시험 환경에서 이벤트 중복·유실·역순, 서비스 중단, 권한 만료, 사용자 정책 대기, 문서 수정이 코드 수정을 유발한 뒤 발생하는 역방향 이벤트를 주입한다. 양방향 자동 반영이 반복 고리에 빠지지 않는지 확인한다. 정상 변경은 초안 검토를 반복 요청하지 않고 끝나며, 승인 없는 원격 쓰기는 발생하지 않아야 한다.

## 완료 조건과 증거

모든 S4 조건을 지원 이벤트별로 검증한다. 자동 종료와 사용자 대기를 구분하고, 반복 운영에서 개입 이유와 복구 결과가 남아야 한다. 한 번의 수동 CLI 성공은 자동 운영 증거가 아니다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 이 조건들은 구현 목표이며 현재 통과 주장으로 읽지 않는다.

## 현재 증거와 남은 일

[스토리 #369](https://github.com/juhyeon-cha/skills/issues/369)의
[M0 #371](https://github.com/juhyeon-cha/skills/issues/371)에서 고정 제품
`efe8c962ab5c0835c2a32f1de8a0e563a11928a6`을 대상으로 로컬 실험을 수행했고,
별도 세션의 독립 품질·수용 판정은 M0 범위에서 LGTM + MATCH다.
상세 관측과 원시 자료 위치는 M0 원장의 `independent-verification` 요약에 기록한다.

- 로컬 주기 실행이 CLI 작업과 독립 리뷰 과제를 선택했다. 최초 세션의 에이전트 생성 한도 실패를 보존하고, 새 세션에서는 실제 독립 모델 5회 호출로 수정 요청·작성·리뷰·B/C 문서 반영을 완료했다. 호스트 에이전트가 모델 전달을 조정하는 경로이며 상시 무인 서비스는 아니다.
- 실제 모델 경로에서 적용 중단(rc91) 후 재개와 완료 재전달의 문서·기준·`complete.json` 보존을 확인했다. 별도 전송 fixture에서도 응답 유실 후 조회·중복 재개를 재현했으며, 이 fixture는 실제 모델 증거와 구분한다.
- 최신 C 뒤 오래된 B를 전달하면 기존 CLI는 새 `awaiting_decisions` 실행으로 접수한다. 후속 이벤트 계층은 오래된 전달과 의도적 되돌림을 구분해야 한다.
- 원본 보존을 위한 복사본의 SQLite 절대 경로 재지정은 이번 격리 실험에 한정한다. 제품이 지원하는 이동식 재개나 무인 인계의 증거가 아니다.

## 구현과 로컬 수용 관측

후속 [태스크 #374](https://github.com/juhyeon-cha/skills/issues/374)는 기존 문서 CLI 위에
명시 코드/목표 요청, 살아 있는 호스트의 모델 작업 전달, 지정 ref의 주기 검사를 연결한다.
설치본은 변경하지 않았다. 운영 방법과 권한·소유권 경계는
[배포용 절차](../../../../plugins/toolkit/skills/refresh-knowledge/references/automation.md)에 있다.

- 이벤트·요청·원인 ID, 입력 커밋과 목표 해시를 보존한다. 오래된 전달은 이력으로 남기고, 의도적 rollback은 근거·영향·선택지를 담은 정책 대기를 거친다.
- 문서 반영과 구현 검증을 별도로 기록한다. 실제 로컬 목표는 코드 커밋·필수 검사·독립 구현 리뷰 후 문서 작성·독립 리뷰·반영까지 완료됐다.
- 반복 timer가 직접 전달하지 않은 새 커밋을 발견했다. 후속 같은 원인의 코드 이벤트와 동일 내용의 새 요청은 별도 이력을 남기면서 모델·문서 효과를 재실행하지 않았다.
- 최초 문서 리뷰의 범위 혼동, 호스트 입력 전달 오류, 변화가 겹친 quiet 시험 실패를 보존했다. 근거 보충과 수정 뒤 같은 실행을 재개했으며 안정된 다섯 tick에서는 재작성·새 모델 과제·반복 알림이 없었다.
- 독립 독자가 운영 문서만으로 초기화·현재 버전 요청·정책 응답·중단/재개를 실행했다. 회귀 검사 17개와 기존 source-contract 67개, 커밋 게이트가 통과했다.

원본 S4-01~06과 15개 사례를 축소하지 않은 대응표 및 실제 응답·명령·산출물은
[로컬 관측 자료](../../../../tests/knowledge/automation/observation/README.md)에 있다.
모델·전송·권한·서비스 실패 주입 회귀는 실제 로컬 CLI 효과를 검사하지만 실제 외부 서비스 장애의 증거는 아니다.
최종 전체 head의 독립 품질·수용 판정과 CI 결과는 기존 PR #372 및 원장에서 확인한다.

지원 경계는 macOS의 단일 로컬 저장소와 살아 있는 호스트, 유한 foreground timer다.
실제 GitHub 이벤트·상시 서비스·운영 예약 연결·원격 게시·설치 활성화는 이번 검증 범위 밖이다.
문서 소유권은 같은 canonical root를 사용하는 협력 자동화끼리의 경계이며 임의 편집자와
중첩·네트워크 root까지의 상호 배제를 보장하지 않는다. DB migration과 상태 경로 이동은 지원하지 않는다.

여러 저장소의 통합 영향 분석과 검색 서비스 고도화는 5단계다.
