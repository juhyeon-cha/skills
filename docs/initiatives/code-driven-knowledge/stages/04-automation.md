# 4단계: 개발 흐름과 자동 연결

검증된 지식 유지 흐름을 개발 이벤트와 정기 검사에 연결하고, 사람에게 실제 결정이 필요한 예외만 전달한다.

[전체 로드맵](../roadmap.md) · 단계 상태: 미착수

## 진입 조건

3단계 유지 흐름이 검증돼야 한다. 대상 저장소·실행 계기·접근 권한·원격 반영 정책을 명시한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S4-01 | 실행 계기 | PR 변경·병합·정기 검사 중 지원하는 계기를 정의하고 이벤트가 가리키는 커밋을 고정한다. 초안과 반영 완료 상태를 구분한다. |
| S4-02 | 순서와 중복 | 이벤트 중복·지연·순서 역전·동시 실행을 처리한다. 같은 변경의 문서 수정·PR 생성·게시 효과가 중복되지 않도록 한다. |
| S4-03 | 실패 운영 | 모델·네트워크·권한·외부 서비스 실패를 분류하고 재시도 가능 여부·중단 기준·재개 위치를 기록한다. 성공하지 않은 외부 반영을 완료로 표시하지 않는다. |
| S4-04 | 사람 개입 | 자동 수정과 정책 결정을 구분한다. 필요한 질문에는 충돌 근거·영향·선택지를 포함하고 응답 후 해당 실행을 이어간다. 사용자 승인 경계를 이벤트 설정으로 우회하지 않는다. |
| S4-05 | 오래된 지식 검사 | 정기 검사로 누락된 이벤트, 기준 불일치, 원본 소실을 발견한다. 미변경 상태는 불필요하게 재작성하거나 알리지 않는다. |
| S4-06 | 운영 관측 | 실행 시간·모델 호출·재시도·사용자 개입 사유를 측정한다. 성공·실패·대기 상태와 실제 산출물을 연결하고 운영자가 실행을 중단·재개할 수 있어야 한다. |

## 필수 판정 시나리오

허용된 시험 환경에서 이벤트 중복·유실·역순, 서비스 중단, 권한 만료, 사용자 정책 대기를 주입한다. 정상 변경은 초안 검토를 반복 요청하지 않고 끝나며, 승인 없는 원격 쓰기는 발생하지 않아야 한다.

## 완료 조건과 증거

모든 S4 조건을 지원 이벤트별로 검증한다. 자동 종료와 사용자 대기를 구분하고, 반복 운영에서 개입 이유와 복구 결과가 남아야 한다. 한 번의 수동 CLI 성공은 자동 운영 증거가 아니다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 이 조건들은 구현 목표이며 현재 통과 주장으로 읽지 않는다.

## 현재 증거와 남은 일

미착수. 현재 실행은 에이전트가 CLI와 리뷰 전달을 조정하며 이벤트 실행·정기 운영·게시 시스템은 없다.

## 제외 범위

여러 저장소의 통합 영향 분석과 검색 서비스 고도화는 5단계다.
