# 2단계: 지식과 명세 구성

코드·문서·사용자 지시·결정에서 현재 지식과 목표 명세를 구성한다. 코드가 없는 새 기능도 목표로 명세할 수 있어야 하며, 현재 구현됐다고 서술하지 않는다.

[전체 로드맵](../roadmap.md) · 단계 상태: 최소 절차 구현·실측 완료 — 최종 수용 판정은 [실행 원장 #355](https://github.com/juhyeon-cha/skills/issues/355) 참조

## 진입 조건

1단계 실행·검증·복구 계약이 성립하고, 단일 저장소의 포함·제외 범위와 독자를 지정할 수 있어야 한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S2-01 | 수집 범위 | 코드·설정·기존 문서·사용자 지시·승인된 결정 기록의 출처와 버전을 고정한다. 문서가 현재 동작 설명인지 제안·확정된 목표인지 구분한다. 누락·접근 불가·제외 항목을 보고하고 의도와 구현의 근거를 구분한다. |
| S2-02 | 지식 구성 | 용어·정책·조건·예외·관계를 추출하고 각 주장에 근거를 연결한다. 현재 사실과 목표 요구를 구분하고 근거 없는 해석은 확정 지식으로 승격하지 않는다. |
| S2-03 | 문서 생성 | 공통 도메인 문서·독자별 안내와 구현 가능한 목표 명세를 생성한다. 목표에는 조건·예외·수용 기준을 포함하고 구현 대기 여부를 표시한다. 공통 정책의 원본을 하나로 두고 직무별 차이는 참조해 설명한다. |
| S2-04 | 범위와 누락 | 선택한 범위의 필수 항목을 수집·문서화·미확정·제외 상태로 대조한다. 문서가 생성됐다는 이유로 수집 범위 전체를 다뤘다고 판단하지 않는다. |
| S2-05 | 독립 검증 | 현재 동작은 구현 근거, 목표는 지시·결정에서 기대 결과를 먼저 고정하고 독립 판정한다. 현재 코드와의 불일치만으로 목표를 실패 판정하지 않는다. 문서만 읽는 풀이자는 코드·정답을 받지 않으며 핵심 시나리오의 행동과 근거를 제시한다. |
| S2-06 | 기준 확정 | 검증된 현재 지식·목표 명세·근거 연결을 각각 버전 관리하고 미반영 차이를 저장한다. 목표 확정과 구현 검증 완료를 분리한다. 같은 입력의 재시도는 중복 문서나 서로 다른 활성 기준을 만들지 않는다. |

## 필수 판정 시나리오

코드만 있는 사례, 문서만 있고 코드가 없는 사례, 사용자 지시로 새 동작을 정의하는 사례에서 구성을 수행한다. 결정 기록 누락, 서로 다른 정책 설명, 필수 예외 누락을 넣어 현재 사실·확정 목표·제안·미확정 항목을 구분하는지 확인한다.

## 완료 조건과 증거

모든 S2 조건을 통과하고 아래 유형별 인계 경로를 실제로 확인해야 한다. 현재 지식은 1단계 갱신 기준으로, 코드 없는 목표는 접수·구현 대기 기록으로 인계한다. 사람이 주장별 연결을 대신 작성했다면 최초 구성 자동화는 완료가 아니다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 이 조건들은 구현 목표이며 현재 통과 주장으로 읽지 않는다.

## 현재 증거와 남은 일

기존 `refresh-knowledge` 진입점에 [최초 구성 절차](../../../../plugins/knowledge/references/bootstrap.md)를 연결했다. 새 CLI·DB·평가 플랫폼 없이 기존 작성·독립 검증·초기화·접수 계약을 사용한다. [실행 태스크 #355](https://github.com/juhyeon-cha/skills/issues/355)에 고정 입력과 실제 역할 응답·명령·해시·실패·재진입 결과를 보존한다. 아래 관측은 macOS/Codex의 합성 단일 저장소·독자 한 유형에 한정하며 최종 독립 수용 판정을 대체하지 않는다.

| 기준 | 실제 관측 |
|---|---|
| S2-01 | 코드 커밋, 사용자 지시, 승인 없는 충돌 문서의 원문·해시를 고정했다. 코드 없음과 필수 근거 접근 불가를 구별하고 후자는 인계하지 않았다. |
| S2-02 | 에이전트가 현재 8개 주장 연결과 목표·미확정 정책을 작성했다. 현재 총 3회와 미구현 목표 총 4회를 분리했다. |
| S2-03 | 공통 계약과 이를 참조하는 호출자 안내, 조건·예외·검증 조건·구현 대기를 가진 목표를 생성했다. |
| S2-04 | 생성 전 필수 항목을 문서 위치와 대조했다. 필수 예외 누락본은 실패하고 30/90일 충돌은 미확정으로 남았다. |
| S2-05 | 새 독자의 문서만 읽는 실제 응답과 독립 판정을 보존했다. 정상본은 통과, 예외 누락·허위 구현 완료는 실패, 없는 근거는 `init`이 거절했다. |
| S2-06 | 현재 `init` 뒤 인자명 변경을 독립 리뷰·`resume` 완료까지 연결했다. 목표는 접수 후 구현 대기로 유지했다. 동일 입력 재진입에서 파일·기준 불변을 확인했고, 제목만 수정한 목표를 다른 경로에 보존하며 논리 ID·이전 버전·접수 ID를 연결했다. |

변경된 출력은 해시 대조로 인계를 중단했다. 이는 절차를 수행하는 에이전트의 검사이며 CLI가 의미 검증을 강제한다는 증거가 아니다. 목표의 동작 변경 이력, 다른 OS·모델·독자, 실제 배포, 저장소 전체 완전성은 미검증이다. 현재 갱신에서 근거 커밋 문장도 바꾸도록 초기 주장 연결에 포함해야 한다는 누락을 발견해 절차에 반영했다.

## 착수 시 적용할 설계 노트

1단계 후속의 [명령 계약·호환성 설계](../design/cli-contract-and-compatibility.md)를 입력으로 삼되, 아래 항목은 2단계 자료 형식을 확정하기 전에 설계한다. 현재 구현 완료를 뜻하지 않는다.

- 실행 진행 상태와 지식의 의미 상태를 별도로 관리한다. 한 실행이 끝났어도 목표는 제안 또는 구현 대기일 수 있다. 기존 `run.phase`의 `completed`를 목표 구현 완료로 사용하지 않는다.
- 현재 사실·목표 명세·근거에 각각 식별자와 버전을 연결한다. 같은 목표가 수정될 때의 논리적 식별자와 내용 버전을 구분하고, 저장소 식별자는 로컬 checkout 경로와 분리한다. 최초 명세 등록 후 수정·이동했을 때 이력이 이어지는 사례로 판정한다.
- 코드가 없는 확정 목표는 유효한 입력이다. 코드 없음·근거 접근 불가·수집 제외를 같은 빈 값으로 합치지 않는다. 승인된 목표와 현재 구현의 차이를 보존하는 사례를 수용 기준에 포함한다.
- DB·산출물 버전은 CLI 계약 버전과 독립이다. 새 자료 형식이 필요하면 호환 범위와 기존 프로젝트의 처리 방침부터 정하고, 1단계의 고정 구버전 자료 검사를 유지한다.

## 제외 범위

목표 명세에 따른 실제 코드 구현, 변경 이력 전체의 자동 처리, 이벤트 실행, 여러 저장소는 후속 단계다.


## 최소 구현 범위

첫 구현은 단일 저장소의 명시한 작은 범위와 지정 독자를 대상으로 한다. 코드는 고정 Git 커밋의 텍스트 파일을 사용하고, 문서·지시·결정은 로컬에 보존한 원문과 출처·버전으로 받는다. 코드 없는 사례에는 코드 근거가 없음을 명시한다. 외부 서비스 수집은 추가하지 않는다.

자동화의 핵심은 에이전트가 근거를 읽어 주장과 연결을 만들고 검증된 결과를 인계하는 것이다. 사용자는 범위·독자·정책을 결정할 수 있지만 주장별 연결을 대신 작성하지 않는다. 첫 사례는 공통 도메인 문서와 독자 한 유형의 안내로 제한한다. 공통 정책을 한 곳에 두고 안내가 이를 참조하는지 확인하며, 직무별 문서 대량 생성은 하지 않는다.

### 남겨야 할 최소 자료

기존 접수·근거 연결·평가 계약에 있는 정보는 재사용한다. 아래 관계를 복원할 만큼만 추가하며, 범용 자료 모델이나 새 데이터베이스를 먼저 만들지 않는다.

| 자료 | 최소 내용 |
|---|---|
| 입력 묶음 | 포함·제외 범위, 독자·목적, 근거 원문·출처·버전·해시, 코드 유무 |
| 필수 항목 목록 | 생성 전에 근거에서 고정한 핵심 조건·예외·목표, 항목 ID, 기대 결과와 근거 |
| 생성 결과 | 공통 문서·필요한 안내·목표 명세, 주장 ID와 근거 연결, 현재/목표/제안 구분 |
| 대조·검증 결과 | 필수 항목별 문서 위치 또는 미확정·제외 이유, 독립 판정, 남은 차이, 인계 결과 |

수집 여부와 문서화 여부는 구별한다. 원문을 읽었어도 필수 예외가 문서에 없으면 누락이다. 필수 항목 목록은 생성 결과에서 역으로 만들지 않으며, 생성 중 새 항목이 발견되면 근거와 기준 변경 이유를 보존하고 추가 검증한다. 파일 수준의 코드 근거 연결을 우선 재사용하되, 코드가 정책 의도의 근거인 것처럼 연결하지 않는다.

### 유형별 인계

| 결과 | 최소 인계와 확인 |
|---|---|
| 코드로 확인한 현재 지식 | 생성 문서와 초기 근거 연결을 기존 `init`에 전달한다. 이어서 고정한 코드 변경 한 건을 기존 갱신 경로로 처리해 연결이 실제 사용됨을 확인한다. |
| 코드 없는 목표 | 기존 `intake` 계약으로 지시·결정·목표·수용 기준·미반영 차이를 보존한다. 생성 명세 버전과 평가 결과를 연결하고 `intake-status`로 재확인한다. 코드 근거나 구현 완료를 만들지 않는다. |
| 현재와 목표가 섞인 결과 | 주장 또는 구간을 분리하고 각각 위 경로로 인계한다. 현재 지식의 기준 확정이 목표의 구현 완료로 전파되지 않는지 확인한다. |

현재 근거 연결은 기존 문서 발췌와 코드 경로를 요구한다. 상세 제약은 [초기 근거 계약](../../../../plugins/knowledge/references/source-contract.md), 코드 없는 목표의 처리는 [접수 계약](../contracts/change-intake.md)을 따른다. 목표를 코드 기반 연결 형식에 억지로 맞추기 위한 스키마 확장은 하지 않는다.

### 미확정과 실패 처리

- 근거가 충돌하거나 필수 정책이 없으면 해당 항목을 미확정으로 남긴다. 필수 항목이 미확정인 묶음은 기준 확정·인계를 중단한다. 독립적인 일부만 확정하는 기능은 첫 구현에 넣지 않는다.
- 접근 불가는 제외로 간주하지 않는다. 필수 근거에 접근할 수 없으면 미실행으로 남긴다. 명시적으로 제외한 범위는 완료 주장에서도 제외한다.
- 생성·검증은 기존 문서를 덮어쓰지 않는 작업 위치에서 수행한다. 실패한 결과와 판정은 보존하고, 첫 구현은 중간 지점 복구 대신 묶음 전체를 다시 생성·검증해도 된다.
- 같은 입력은 원문 버전·해시, 범위, 독자·목적이 모두 같은 경우다. 동일 입력 재시도는 기존 완료 기록을 확인하며 새 활성 기준을 만들지 않는다. 결과 파일이 달라졌으면 재사용하지 않고 불일치를 보고한다. 입력이 달라지면 별도 묶음으로 다룬다.
- 검증 후 인계 중 종료됐으면 기존 `status`·`intake-status`로 반영 여부를 먼저 확인한다. 확인할 수 없으면 추가 인계를 중단한다. 새 복구 엔진이나 기존 DB 마이그레이션은 만들지 않는다.

## 구현 순서와 통과 사례

각 작업은 해당 S2 조건의 증거를 남긴다. 첫 작업에서 계약의 실제 부족분을 확인한 뒤 필요한 검사·연결 코드만 추가한다. 공개 명령이나 새 스킬의 추가는 기존 진입점으로 수행할 수 없는 이유가 확인될 때 결정한다.

| 순서 | 작업과 고정 사례 | 관찰할 통과 결과 |
|---|---|---|
| 1 | 코드만 있는 작은 사례: 정상 조건과 예외가 있는 동작, 공통 문서와 독자 안내 생성 | 사람이 주장 연결을 쓰지 않아도 필수 항목과 근거가 연결된다. 독립 검토·문서만 읽는 풀이를 통과하고 `init` 뒤 변경 한 건의 갱신까지 연결된다. S2-01~06의 현재 지식 경로를 확인한다. |
| 2 | 문서만 있는 사례와 사용자 지시의 새 동작 사례: 코드 없음, 혼합 문서, 결정 누락·정책 충돌 포함 | 승인 근거 없는 문서는 제안·미확정으로 남고 명시적 지시는 확정 목표로 구분된다. 조건·예외·수용 기준을 가진 목표가 코드와 다르다는 이유로 실패하지 않으며, 미확정 필수 정책은 인계를 막는다. S2-01~06의 목표 경로를 확인한다. |
| 3 | 정상본의 결함 사본과 재시도: 필수 예외 누락, 미구현 목표를 현재 동작으로 표현, 깨진 근거 연결, 생성 후·인계 후 종료 | 정상본은 통과하고 각 결함은 대응 기준에서 실패한다. 재시도 후 활성 기준과 문서가 중복되지 않으며 실패 증거가 남는다. S2-04~06과 복구 경계를 확인한다. |

질문·기대 명제는 생성 전에 고정한다. 독립 역할의 입력 분리와 실제 응답 보존은 [방법론](../methodology.md#3-판정-역할과-입력을-분리한다)을 재사용한다. 위 사례가 통과하기 전에는 저장소 전체의 완전성이나 다른 독자의 이해도를 주장하지 않는다.

## 필요가 확인될 때까지 보류할 것

범용 지식 그래프·관계 추론, 자동 전체 저장소 탐색, 외부 자료 커넥터, 여러 독자용 대량 생성, 새 검색·평가 플랫폼, 부분 확정과 세밀한 중간 복구는 만들지 않는다. 사례 수행에 반복적으로 필요한 자료 준비·형식 검사만 작은 도구로 분리한다. 기존 파일·JSON 계약으로 충분하면 추가 저장 계층은 도입하지 않는다. 문서→코드 구현과 변경에 따른 문서 통합·폐기는 3단계 범위를 유지한다.
