# 5단계: 여러 저장소의 일관성 관리와 고도화

여러 저장소의 현재 구현·목표 명세·결정을 연결해 검색·위키와 개발 판단에 제공한다. 문서나 코드에서 시작한 변경의 전체 영향과 저장소별 미반영 차이를 추적한다.

[전체 로드맵](../roadmap.md) · 단계 상태: 미착수

## 진입 조건

4단계 자동 운영이 검증돼야 한다. 연결할 저장소·접근 범위·사용자의 질문과 개발 판단 시나리오를 정한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S5-01 | 저장소 간 근거 | 서비스·계약·정책의 연결을 저장소와 버전별로 식별한다. 부분 갱신과 접근 불가를 숨기지 않으며 서로 다른 버전을 최신 전체 상태로 표현하지 않는다. 하나의 목표에 대한 저장소별 구현 대기·검증 완료 상태를 구분한다. |
| S5-02 | 검색과 위키 | 조회 결과에서 근거·현재 구현 버전·목표 버전·미구현 또는 미확정 상태를 확인한다. 검색·위키는 검증된 지식의 표현이며 별도의 사실 원본으로 분기하지 않는다. |
| S5-03 | 개발 전후 연결 | 사용자 지시·문서·코드 어느 출발점이든 개발 전 영향 예측을 남기고 개발 후 실제 변경·검증과 비교한다. 예측 누락과 새 결정이 지식 유지 흐름으로 돌아간다. |
| S5-04 | 권한과 게시 | 원본 접근 권한과 조회·게시 범위의 관계를 정한다. 권한 밖 근거를 노출하지 않고 게시 실패·부분 반영·철회 결과를 추적한다. |
| S5-05 | 품질과 비용 | 실제 질문의 정답 근거와 실패 사례로 검색·문서 판단 품질을 평가한다. 기존 방식과의 차이, 비용·지연·사용자 개입을 측정한 뒤 개선안을 선택한다. |
| S5-06 | 도구 도입 판단 | 전체 흐름의 관측된 병목에 따라 검색·실행·평가 부품을 비교한다. Promptfoo 등 평가 플랫폼은 이 단계의 검토 후보이며 도입하지 않는 결론도 허용한다. |

## 필수 판정 시나리오

선정한 여러 저장소의 코드 선행 변경과 문서 선행 계약 변경 각각으로 영향 판단→문서·코드 반영→구현 검증→검색·위키 확인을 수행한다. 부분 권한, 한 저장소만 구현 완료된 상태, 목표 철회, 한 저장소의 갱신 실패, 오래된 색인, 잘못된 영향 예측을 포함한다.

## 완료 조건과 증거

모든 S5 조건을 선정한 사용 시나리오와 권한 범위에서 검증하고, 개발 전후 판단이 같은 근거 체계로 연결돼야 한다. 목표 품질·비용 기준은 실험 전에 별도로 정하며 현재 수치를 약속하지 않는다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 이 조건들은 구현 목표이며 현재 통과 주장으로 읽지 않는다.

## 현재 증거와 남은 일

미착수. 여러 저장소·검색·위키·평가 플랫폼 도입과 일반적인 의미 정확성은 현재 PR의 검증 범위가 아니다.

## 제외 범위

관측하지 않은 저장소·언어·제품의 정확성이나 완전 무인 운영을 보장하지 않는다.
