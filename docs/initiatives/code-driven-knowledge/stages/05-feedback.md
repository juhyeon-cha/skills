# 5단계: 여러 저장소의 일관성 관리와 고도화

여러 저장소의 현재 구현·목표 명세·결정을 연결해 검색·위키와 개발 판단에 제공한다. 문서나 코드에서 시작한 변경의 전체 영향과 저장소별 미반영 차이를 추적한다.

[전체 로드맵](../roadmap.md) · 단계 상태: S5-01~06 로컬 실측 완료 — 최종 수용·전달 판정은 [원장 #395](https://github.com/juhyeon-cha/skills/issues/395)

## 진입 조건

4단계 자동 운영이 검증돼야 한다. 연결할 저장소·접근 범위·사용자의 질문과 개발 판단 시나리오를 정한다.

## 실험에 적용한 설계 노트

- 하나의 목표 아래 저장소별 구현 버전·검증 결과를 유지한다. A 저장소 완료·B 저장소 대기를 전체 완료로 합치지 않는다. 서로 다른 관측 시점과 접근 불가도 결과에 드러내는 사례로 판정한다.
- 저장소의 논리적 ID, 로컬 경로, 원격 URL을 같은 값으로 취급하지 않는다. 이동·복제 후에도 근거가 이어져야 하며, 공유 목표 ID와 저장소별 결과 ID의 관계를 먼저 정한다.
- 검색·위키 색인은 재생성 가능한 조회용 자료로 두고 원본 지식·목표·근거의 권위를 대신하지 않게 한다. 현재 동작과 미구현 목표를 분리하고 색인 지연·삭제·권한 철회 시 노출 규칙을 검증한다.
- 여러 저장소 전체를 한 번에 원자적으로 반영한다고 가정하지 않는다. 부분 완료·게시 실패·철회 상태를 조회할 수 있는 계약부터 정한다. 중앙 DB·분산 실행·검색 엔진 도입은 실제 규모와 병목을 관측한 뒤 선택한다.

현재 구현의 권한·식별자·부분 검증·조회 계약은 [다중 저장소 참조](../../../../plugins/toolkit/skills/refresh-knowledge/references/multi-repo.md), 설계 노트의 실제 검증 범위는 [실측 보고](../experiments/multi-repo-observation.md)를 따른다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S5-01 | 저장소 간 근거 | 서비스·계약·정책의 연결을 저장소와 버전별로 식별한다. 부분 갱신과 접근 불가를 숨기지 않으며 서로 다른 버전을 최신 전체 상태로 표현하지 않는다. 하나의 목표에 대한 저장소별 구현 대기·검증 완료 상태를 구분한다. |
| S5-02 | 검색과 위키 | 조회 결과에서 근거·현재 구현 버전·목표 버전·미구현 또는 미확정 상태를 확인한다. 검색·위키는 검증된 지식의 표현이며 별도의 사실 원본으로 분기하지 않는다. |
| S5-03 | 개발 전후 연결 | 사용자 지시·문서·코드 어느 출발점이든 개발 전 영향 예측을 남기고 개발 후 실제 변경·검증과 비교한다. 예측 누락과 새 결정이 지식 유지 흐름으로 돌아간다. |
| S5-04 | 권한과 게시 | 원본 접근 권한과 조회·게시 범위의 관계를 정한다. 권한 밖 근거를 노출하지 않고 게시 실패·부분 반영·철회 결과를 추적한다. |
| S5-05 | 품질과 비용 | 실제 질문의 정답 근거와 실패 사례로 검색·문서 판단 품질을 평가한다. 기존 방식과의 차이, 비용·지연·사용자 개입을 측정한 뒤 개선안을 선택한다. |
| S5-06 | 도구 도입 판단 | 전체 흐름의 관측된 병목에 따라 검색·실행·평가 부품을 비교한다. Promptfoo 등 평가 플랫폼은 이 단계의 검토 후보이며 도입하지 않는 결론도 허용한다. |

## 필수 판정 시나리오

선정한 여러 저장소의 코드 선행 변경과 문서 선행 계약 변경 각각으로 영향 판단→문서·코드 반영→구현 검증→검색·위키 확인을 수행한다. 부분 권한, 한 저장소만 구현 완료된 상태, 목표 철회, 한 저장소의 갱신 실패, 오래된 색인, 잘못된 영향 예측을 포함한다.

## 완료 조건과 증거

모든 S5 조건을 선정한 사용 시나리오와 권한 범위에서 검증하고, 개발 전후 판단이 같은 근거 체계로 연결돼야 한다. 목표 품질·비용 기준은 실험 전에 별도로 정하며 현재 수치를 약속하지 않는다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 원본 조건은 [고정한 사본](../../../../tests/knowledge/multi_repo/observation/original-stage5.md)으로 보존했다.

## 현재 증거와 남은 일

[실측 보고](../experiments/multi-repo-observation.md)는 코드 선행·문서 선행 전체 흐름과 원본 필수 실패 시나리오, 사용자 출발점, 실제 독립 모델 응답, 같은 여섯 질문의 비교를 연결한다. 양쪽 독자의 여섯 답변은 별도 평가에서 정답·근거·비공개 처리 모두 통과했다. 원문 조회 작업 120회와 관리 조회 12회는 입력 준비 관측이며 비용·속도·일반 사용성 우월성의 근거는 아니다.

운영 저장소·서비스·계정 연결, 설치본 활성화, 일반 규모·언어 정확성은 미검증이다. 추가 중앙 DB·검색 엔진·Promptfoo는 관측한 병목에 근거해 도입하지 않았다. 최종 head의 독립 품질·수용 평가와 CI·병합은 위 원장에서 확인한다.

## 제외 범위

관측하지 않은 저장소·언어·제품의 정확성이나 완전 무인 운영을 보장하지 않는다.
