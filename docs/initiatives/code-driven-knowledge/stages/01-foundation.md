# 1단계: 변경 의도와 실행 기반

사용자 지시·문서·코드의 변경을 받아 출발점, 근거의 권위, 현재 상태와 목표 상태를 구분하는 실행 기반을 확립한다. PR #332의 [기존 최종 검증](../experiments/foundation-verification.md)은 당시 범위에서 완료를 판정했다. 접수 원문과 리뷰 연결 및 손상 context 재진입 결함이 확인되어, 아래 18개 고정 기준으로 수정본을 재검증했고 [후속 독립 판정](../experiments/foundation-followup.md)에서 모두 충족했다.

[전체 로드맵](../roadmap.md) · 단계 상태: 완료 — 명시된 macOS/Codex 개발 패키지·독립 child 범위

## 진입 조건

단일 프로젝트의 코드·문서·지시·결정 중 사용 가능한 입력과 버전을 고정한다. 독자·목적·실행 환경을 정하고 최초 연결은 준비된 입력으로 허용한다. 코드나 문서가 아직 없으면 없음으로 기록하며 구현된 것으로 추정하지 않는다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S1-01 | 지원 범위와 설치 | 지원 호스트·Python/Git 의존성·입력 제약을 명시하고, 개발 저장소 없이 패키지로 설정부터 실행한다. 지원하지 않는 환경은 시작 전에 원인을 안내한다. |
| S1-02 | 자료와 역할 계약 | 근거·주장·문서·수정안·리뷰·완료 기록의 버전과 연결을 정의한다. 출발점과 변경 의도, 권위 있는 근거, 현재·목표 버전, 미반영 차이를 연결한다. 단계별 입력·출력·책임·불변 조건을 추적할 수 있으며 스킬 의존성 누락은 통과가 아니다. |
| S1-03 | 하나의 실행 흐름 | 접수→의도 분류→현재·목표 비교→작업 경로 선택을 연결한다. 코드→문서 경로는 작성·독립 리뷰·반영까지 실행하고, 문서→코드는 구현할 요구와 남은 차이로 인계한다. 새 세션이 프로젝트 위치와 실행 ID로 이어받고 사용자가 자료 인자를 다시 조립하지 않는다. |
| S1-04 | 복구와 수명주기 | 중복·동시 요청·중단·손상 기록·문서 충돌마다 다음 행동을 정한다. 계속할 수 없는 실행의 종료 또는 격리, 범위 변경 시 새 프로젝트 전환을 포함해 사용자를 막다른 상태에 두지 않는다. |
| S1-05 | 문서 검증 | 현재 동작 설명은 구현 근거로, 목표 명세는 사용자 지시·승인된 결정과 수용 기준으로 검증한다. 사실·예외·판단 가능성·근거 추적·일관성·불확실성 기준을 고정한다. 리뷰 실패 후 수정·재리뷰를 실제 수행하고 잘못된 문서가 해당 기준에서 실패함을 확인한다. |
| S1-06 | 설치 사용자 관측 | 동일한 설치 환경에서 최초 설정, 리뷰 반려·수정, 적용 중단·재개, 다음 코드 변경을 이어서 관측한다. 문서의 표현 변경·동작 변경·사용자 지시도 접수해 올바른 경로와 상태로 분류하는지 확인한다. 도구가 실제 읽은 파일과 결과, 사용자 개입을 기록한다. |

## 필수 판정 시나리오

기존 문서가 있는 저장소의 두 연속 변경을 수행한다. 정상 흐름 외에 예외 설명 누락, 오래된 리뷰, 독립 문서 편집, 중간 종료, 손상 기록, 의존 스킬 누락을 포함한다. 각 실패는 잘못된 반영을 막고 문서화한 재개·종료 경로로 끝나야 한다. 목표 문서가 현재 코드와 다를 때 문서를 되돌리거나 구현 완료로 오판하지 않아야 한다. 표현만 바꾼 문서에서 불필요한 코드 작업을 만들지 않는다.

## 완료 조건과 증거

모든 S1 조건을 동일한 지원 범위에서 검증하고 현재 계약과 실제 관측의 차이를 해소한다. 부품 테스트 통과만으로 완료하지 않는다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 현재 판정의 범위와 원본은 아래 최종 검증에 연결한다.

## 현재 증거와 남은 일

K1–K5와 [초기 보완 관측](../experiments/foundation.md)의 실패 기록은 보존한다. [최종 검증](../experiments/foundation-verification.md)은 최종 패키지에서 새 작성·리뷰 응답, 두 연속 변경, 적용 중단과 새 컨텍스트의 공개 CLI 재개를 확인했다. 당시 독립 평가 결과는 모든 S1 조건 MET였으며 이 관측 원본은 보존한다. 이 결과를 새 접수 결합 패킷의 실제 리뷰나 아래 18개 기준의 현재 판정으로 전용하지 않는다. 앱 재시작·새 최상위 데스크톱 작업·marketplace 자동 로딩·다른 OS는 미검증이며 이 완료 판정에 포함하지 않는다.

## 제외 범위

문서→코드의 실제 구현·검증 완료는 3단계다. 이 단계는 해당 작업의 인계와 미구현 상태 표시까지 다룬다. 새 문서·새 주장 자동 생성, PR 이벤트, 원격 게시, 여러 저장소는 포함하지 않는다.

[초안 기능 검증 K1–K5](../acceptance.md), [문서 AC 실험](../experiments/document-ac.md), [설치 실행 관측](../experiments/installed-workflow.md), [현재 실행 계약](../contracts/agent-workflow.md)을 근거로 사용한다.

## 승인된 고정 수용 기준

각 행을 pass/fail/not-executed/indeterminate로 판정하고 현재 소스·설치 버전과 원본 근거를 연결한다. 기준 변경은 이유와 이전 판정을 보존한다. 테스트, 저장 응답 재생, 실제 새 모델 관측을 구분한다.

| ID | 통과 기준 |
|---|---|
| S1-01-a | 개발 저장소 없이 복사 패키지에서 doctor→init→start 성공, 실제 의존성·입력 제약 기록. 의존성 누락은 변경 전 거절 |
| S1-01-b | 지원 호스트에서 작성·독립 리뷰·새 컨텍스트 인계 주체가 실제 필요한 도구를 실행. 파일 존재나 Python 자식 프로세스만으로 대체하지 않음 |
| S1-02-a | 출발점·의도·권위·현재/목표 버전·AC·미반영 차이를 원문까지 추적. 누락·변조·잘못된 참조 거절 |
| S1-02-b | 접수 원문 전체가 리뷰 패킷 ID에 결합. 코드·수정안은 같고 AC 또는 권위만 다르면 패킷 ID가 다르며 과거 리뷰 거절, 문서·기준 불변 |
| S1-02-c | 과거 관측 원본은 그대로 재생. 접수 누락 과거 리뷰로 새 접수 검증을 통과시키지 않음 |
| S1-03-a | 동일 프로젝트에서 코드 접수→작성→독립 반려→수정→새 리뷰→적용→다음 코드 변경 연결 |
| S1-03-b | 실제 분류에서 표현 변경은 의미 비교 후 코드 작업 불필요, 문서 동작 변경·사용자 목표는 목표·차이·AC를 가진 구현 대기. 분류만으로 문서·구현·배포 완료가 되지 않음 |
| S1-03-c | 이전 대화 없이 프로젝트 위치·실행 ID·설치 진입점만 받은 실행 주체가 미완료 실행을 이어 완료. 부모 대리 실행이나 이미 완료된 실행 조회는 대체 증거가 아님 |
| S1-04-a | 동일 요청은 동일 실행 반환. 경쟁 쓰기·다른 활성 요청은 문서·기준 변경 없이 거절 |
| S1-04-b | context·packet·completion 손상 탐지 및 원본 보존. context의 잘못된 JSON·내용 변조·누락·심벌릭 링크 각각 복구 또는 종료 경로 확인 |
| S1-04-c | 적용 중 종료 후 같은 실행 재개 시 정확한 문서·완료 기록, 기준은 한 번 전진. 독립 편집은 보존하고 충돌 안내 |
| S1-04-d | 적용 전 종료·부분 적용 격리·범위 변경 후 새 기준 전환. 손상 DB 보존 및 새 프로젝트 안내, 격리 성공으로 허위 표시하지 않음 |
| S1-05-a | 현재·목표·표현 문서의 권위·필수 명제·질문·입력 바이트를 관측 전에 고정 |
| S1-05-b | 예외 누락·거짓 완료 문서는 대응 기준 실패, 수정본은 새 리뷰 통과. 변경 문서에 옛 응답 재사용 금지 |
| S1-05-c | 코드 설명은 맞지만 접수 AC를 빠뜨린 수정안을 실제 독립 리뷰가 반려 |
| S1-06-a | 최종 소스와 설치 해시 일치. 같은 설치에서 설정·반려/수정·중단/재개·두 번째 변경 관측, 실제 읽기·응답·사용자 개입 보존 |
| S1-06-b | 같은 설치에서 코드·문서 표현·문서 동작·사용자 지시의 실제 분류 및 새 컨텍스트 인계. 준비된 JSON 수용 검사와 구분 |
| S1-06-c | 모든 조건의 현재 버전 판정·증거/미실행 사유가 독립 최종 검토와 일치. 필수 미충족이 남으면 전체 완료 보류 |


새 실험 결과와 행별 판정은 기준과 분리해 [후속 검증 기록](../experiments/foundation-followup.md)에 연결한다. 필수 미충족이 남으면 전체 완료를 선언하지 않는다.
