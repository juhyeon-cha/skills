# 3단계: 양방향 변경 반영

코드→문서와 문서→코드 양방향으로 변경을 반영한다. 사용자 지시에 따라 순서를 선택하고 목표 명세와 현재 구현의 미반영 차이를 검증이 끝날 때까지 추적한다.

[전체 로드맵](../roadmap.md) · 단계 상태: 로컬 수용 완료 — macOS/Codex 합성 시나리오 범위

## 진입 조건

2단계에서 검증한 최초 지식과 근거 연결을 사용하며, 처리할 변경 전후 버전과 적용 순서를 고정한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S3-01 | 변경 분류 | 출발점과 함께 표현 보완·현재 설명 정정·동작 또는 정책 변경을 분류한다. 추가·수정·삭제·이동·이름 변경 후보와 결정 변경도 구분한다. 파일 이동을 정책 동일성으로 단정하지 않는다. |
| S3-02 | 영향 분석 | 코드 변경에서 영향 문서를, 문서·목표 변경에서 영향 코드·테스트·계약을 식별한다. 공통 정책의 간접 참조와 미연결 항목도 검토한다. 영향 없음 판정도 근거와 함께 남긴다. |
| S3-03 | 반영과 구현 | 코드 변경은 의도와 대조한 뒤 문서에 반영한다. 확정 목표에서 코드·테스트를 구현하고 독립 리뷰·동작 검증 후 구현 상태를 갱신한다. 새 주장·문서 생성, 통합·폐기도 연결한다. |
| S3-04 | 충돌 처리 | 코드·결정·문서 간 충돌을 탐지하고 승인된 미구현 차이와 결함을 구분한다. 기존 코드로 목표 문서를 덮어쓰거나 잘못된 코드를 문서화해 정당화하지 않는다. 근거로 해소할 수 있는 수정은 내부 처리하고 정책 선택만 사용자에게 요청한다. |
| S3-05 | 순서와 재처리 | 연속·중복·역순 변경과 실패 후 재개에 대해 기준 일관성을 유지한다. 검토된 목표·코드·문서 기준이 바뀌면 재검토하며, 문서 반영 뒤 코드 실패 시 구현 대기 상태와 차이를 보존한다. 되돌림·보류·철회 시 양쪽 영향도 추적한다. |
| S3-06 | 색인과 추적 | 문서·코드·테스트·결정·색인을 현재 버전과 목표 버전으로 연결한다. 미구현 목표가 현재 동작의 검색 결과로 섞이지 않아야 한다. 현재 주장에서 원본과 변경 이유로, 변경에서 영향 문서로 추적할 수 있다. |

## 필수 판정 시나리오

2단계 산출물에 코드 선행 변경, 문서 선행 동작 변경, 표현만 수정, 사용자 지시의 새 기능을 적용한다. 목표가 바뀐 뒤 오래된 코드 결과 도착, 문서 반영 후 구현 실패, 목표 철회, 삭제·이름 변경도 포함한다. 역순·중복 요청과 문서 충돌을 포함하고 영향받지 않아야 할 문서의 보존도 확인한다.

## 완료 조건과 증거

모든 S3 조건을 양방향으로 검증하고 예상 영향과 실제 수정·보존 결과가 일치해야 한다. 목표의 모든 수용 기준에 구현 검증 근거가 있어야 차이 해소로 판정하며, 실패 뒤에는 유효 기준·미반영 차이·이력을 복구해야 한다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 아래 판정은 이 원본 조건을 유지한 채 고정 시나리오에서 확인한 결과다. 운영 환경 전체의 보장은 아니다.

## 현재 증거와 남은 일

S3-01~06과 필수 시나리오 전체를 기존 CLI와 에이전트 절차로 검증했다. M0·M1의 문서→코드 구현 검증, [M2 실험 #365](https://github.com/juhyeon-cha/skills/issues/365), [M3 절차·최종 독립 판정 #367](https://github.com/juhyeon-cha/skills/issues/367)을 연결한다. 제품 절차 판정 커밋은 `958736653fb55b5c87eee6b0d8e238f32267d783`이며, 원격 전달과 설치 활성화는 별도다.

| 조건 | 확인한 결과 |
|---|---|
| S3-01 | 표현 수정·현재 설명·목표·결함을 분류하고, 3→4회 정책 변경을 동반한 이름 변경을 단순 이동과 구분했다. |
| S3-02 | 공통 정책의 간접 호출자까지 영향받는 문서를 수정하고 독립적인 health 문서·소스의 보존을 확인했다. |
| S3-03 | 문서 선행 목표의 실패→구현 통과→의도적 결함 재검출과 코드 선행 문서 갱신을 확인했다. 새 기능·주장은 검토된 후속 묶음으로 초기화하고 이전 문서를 논리적으로 폐기했다. |
| S3-04 | 문서가 반영된 뒤 구현 실패를 미반영 차이로 남겼고 문서 충돌 바이트와 이전 기준을 보존했다. 잘못된 코드로 목표를 덮어쓰지 않았다. |
| S3-05 | 늦은 옛 성공·중복·역순·실패 재개·보류·철회에서 유효 기준과 이력을 유지했다. 되돌림은 현재 v3·복원 후보 v1·남은 차이 추적까지 확인했으며 실제 복원 완료는 검증하지 않았다. |
| S3-06 | 현재 주장→정확한 문서·소스·테스트·원결정과 변경→영향 문서를 대조했다. 현재·목표·폐기 항목을 분리하고 색인을 문서와 같은 검토·적용 범위에 포함했다. |

원결정 연결 오류와 첫 갱신 묶음의 색인 누락은 실패로 보존한 뒤 수정본만 새 검토를 받았다. 최종 절차의 첫 독자 관찰도 세 가지 필수 설명 누락으로 수용 실패했다. 기대 기준을 유지하고 질문의 하위 상황을 명시한 뒤, 이전 답안을 보지 않은 새 독자와 별도 평가자가 여섯 사례를 재판정했다. 최초 실패를 통과로 바꾸지 않았다.

설치되는 [refresh-knowledge 진입점](../../../../plugins/toolkit/skills/refresh-knowledge/SKILL.md)은 구현 검증과 구조·간접 영향·색인·철회 절차를 조건부로 연결한다. CLI의 불변 접수 기록은 그대로이며 최신 목표 선택과 의미 검증은 호출 에이전트가 담당한다. 새 DB·명령·상태 또는 검색 엔진은 추가하지 않았다.

로컬 원본은 `/private/tmp/stage3-work/`에 보존했다. `m0/reproduction-map.json`은 역사 소스·테스트의 정확한 Git blob을, `full/m2/commands/`는 111개 실행의 입력·종료 코드·원시 출력을, `full/m3/`는 두 독자 응답과 독립 판정을 연결한다. 이 로컬 경로는 저장소를 복제해도 함께 제공되지 않는다. 판정과 종료 근거는 위 실행 원장에 남긴다. 필수 gate와 설치 묶음 내부 참조 검사는 통과했으며, 제품 실행 코드가 바뀌지 않아 전체 개발 회귀는 반복하지 않았다.

검증 환경은 로컬 macOS/Codex 합성 저장소다. 실제 되돌림 복원 실행, 운영 배포, 설치 활성화, 다른 OS 및 4~5단계는 미검증이다.

## 후속 단계에 넘기는 설계 노트

- 2단계에서 정한 목표 ID·버전에 문서 반영 결과와 코드 검증 결과를 각각 연결한다. 하나의 실행 성공으로 둘을 완료 처리하지 않는다. “문서 반영 성공·코드 구현 실패”가 유효한 중간 상태로 남는 사례를 먼저 고정한다.
- 재개와 오래된 결과 거절의 단위는 검토한 목표·소스·문서 버전 묶음이다. 목표가 바뀐 뒤 이전 결과가 도착하면 새 목표를 완료로 바꾸지 않는다. 목표 철회 시 과거 근거를 보존한다.
- 동일 내용의 산출물 식별자와 같은 요청의 재전달을 구분한다. 로컬 반영 효과와 이를 유발한 실행을 연결할 위치를 정해 4단계의 이벤트 순환 차단에 넘긴다. 이벤트 전송·스케줄러는 여기서 구현하지 않는다.
- 기존 `resume` 복구와 구버전 자료 검사를 유지하며 양방향 반영의 중간 실패를 추가한다. 전체 변경을 하나의 트랜잭션으로 묶을 수 있다고 가정하지 않는다.

이 노트의 목표·증거 연결은 위 로컬 범위에서 검증했다. 이벤트 전송·자동 순환 차단과 운영 환경의 복구 보장은 후속 범위로 남는다.

## 제외 범위

PR 이벤트 구독·스케줄러·원격 게시·저장소 간 영향은 포함하지 않는다.
