# 코드 기반 지식 자동화

코드에서 근거를 수집하고 지식을 갱신한 뒤, 독자에게 필요한 문서를 작성·검증하는 흐름을 여러 스킬로 연결한다. 이 디렉터리는 전체 목표와 설계 판단, 실험 결과를 축적하는 시작점이다. 현재 PR #328은 1단계 초안이며 전체는 5단계로 진행한다.

## 1단계 초안의 역할별 구현 상태

| 역할 | 책임 | 현재 상태 |
|---|---|---|
| 근거 수집·변경 추출 | 코드·설정·결정 기록의 버전과 출처를 확보하고 변경분을 추출한다 | 고정 Git 텍스트 수집·파일 변경 비교 CLI 구현. 심벌·정책 영향 추출은 미구현 |
| 지식 갱신 | 영향받는 공통 지식과 근거 연결을 갱신한다 | 근거 연결·후보 추출·에이전트 결정 검증·조건부 문서 적용 CLI 구현. 설치 스킬과 프로젝트 CLI로 연결. 복사한 패키지 실행 검증 |
| 문서 작성 | 독자의 행동·판단에 맞춰 지식을 설명한다 | 기존 `writing-for-humans` 사용 |
| 문서 검증 | 사실·예외·인용을 검증하고 실패를 작성 단계로 돌려보낸다 | review-knowledge 설치 스킬 구현. 실제 독립 리뷰 관측 |
| 실행 관리 | 작업 순서·재시도·완료 상태를 관리한다 | refresh-knowledge와 프로젝트 CLI가 기준 승계·상태·재개를 관리. 백그라운드 무인 실행은 미구현 |

위 표는 부품별 구현 상태이며 단계 완료 판정이 아니다. 역할 하나가 반드시 스킬 하나를 뜻하지는 않는다. 단계별 조건을 구체화할 때 기존 스킬의 재사용과 자료 계약을 먼저 정한다.

Promptfoo와 LLM 응답 평가 고도화는 전체 흐름 구현 이후로 미룬다. 현재는 근거·변경분 계약과 결정적 처리부터 구현한다.

## 자료를 쌓는 기준

- 전체 순서와 상태는 `roadmap.md`, 단계별 상세 조건은 `stages/`에서 관리한다. `acceptance.md`는 현재 PR의 기능 검증 기록이다.
- 설계가 구체화되면 책임과 입력·출력 계약을 이 디렉터리에 기록하고 이 목록에서 연결한다. 아직 결정하지 않은 내용을 확정된 설계로 쓰지 않는다.
- 실험 결과는 `experiments/`에 사례별로 남긴다. 결론·실패·한계와 다음 판단을 기록하고 실행 자료를 연결한다.
- 재실행 코드와 고정 입력·관측 원본은 `tests/knowledge/`에 둔다. 과거 관측을 새 결과로 덮어쓰지 않는다.
- `plugins/`의 스킬에는 여러 프로젝트에서 재사용할 실행 지침을 둔다. 이 작업의 계획과 진행 이력은 여기서 관리한다.

첫 실험은 원래 `tests/toolkit/writing-for-humans/`에 있었지만, 문서 작성 스킬의 책임보다 넓은 평가 절차이므로 `tests/knowledge/document-ac/`로 옮겼다. 과거 실행 기록에 남은 옛 경로는 당시 관측의 일부로 보존한다.
