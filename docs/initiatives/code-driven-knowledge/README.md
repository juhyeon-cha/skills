# 코드 기반 지식 자동화

코드에서 근거를 수집하고 지식을 갱신한 뒤, 독자에게 필요한 문서를 작성·검증하는 흐름을 여러 스킬로 연결한다. 이 디렉터리는 전체 목표와 설계 판단, 실험 결과를 축적하는 시작점이다.

## 읽는 순서

| 알고 싶은 것 | 문서 |
|---|---|
| 단기·중기·장기 목표와 완료 조건 | [로드맵](roadmap.md) |
| 무엇을 재사용하고 CLI·에이전트에 맡길 것인가 | [부품과 책임 경계 조사](research/components-and-boundaries.md) |
| 문서 AC 평가에서 실제로 확인한 것 | [첫 실험 결과](experiments/document-ac.md) |
| 평가를 다시 실행하는 방법과 입력·검사 코드 | [문서 평가 사례](../../../tests/knowledge/document-ac/README.md) |

실행 상태와 태스크별 수용 기준은 원장에서 관리한다. [첫 스토리 #323](https://github.com/juhyeon-cha/skills/issues/323)은 한 사례의 작성·평가·수정 실험을 완료했다. 여러 스킬을 연결한 자동화 전체가 완성된 상태는 아니다.

## 역할과 현재 상태

| 역할 | 책임 | 현재 상태 |
|---|---|---|
| 근거 수집·변경 추출 | 코드·설정·결정 기록의 버전과 출처를 확보하고 변경분을 추출한다 | 고정 사례만 확보. 재사용 가능한 스킬과 변경 추출은 미구현 |
| 지식 갱신 | 영향받는 공통 지식과 근거 연결을 갱신한다 | 로드맵 단계. 입력·출력 계약과 구현은 미확정 |
| 문서 작성 | 독자의 행동·판단에 맞춰 지식을 설명한다 | 기존 `writing-for-humans` 사용 |
| 문서 검증 | 사실·예외·인용을 검증하고 실패를 작성 단계로 돌려보낸다 | 개발용 평가 사례와 재실행 절차 구현. 범용 스킬은 미구현 |
| 실행 관리 | 작업 순서·재시도·완료 상태를 관리한다 | 기존 하네스 사용. 지식 갱신 전체 흐름의 자동 연결은 미구현 |

역할 하나가 반드시 스킬 하나를 뜻하지는 않는다. 다음 설계에서는 기존 스킬의 재사용 범위와 단계 사이에 전달할 근거·변경분·문서·판정의 형태를 먼저 정한다. 그 결과로 새 스킬이 필요한 책임을 구분한다.

## 자료를 쌓는 기준

- 목표와 단계 완료 조건은 `roadmap.md`에서 갱신한다.
- 설계가 구체화되면 책임과 입력·출력 계약을 이 디렉터리에 기록하고 이 목록에서 연결한다. 아직 결정하지 않은 내용을 확정된 설계로 쓰지 않는다.
- 실험 결과는 `experiments/`에 사례별로 남긴다. 결론·실패·한계와 다음 판단을 기록하고 실행 자료를 연결한다.
- 재실행 코드와 고정 입력·관측 원본은 `tests/knowledge/`에 둔다. 과거 관측을 새 결과로 덮어쓰지 않는다.
- `plugins/`의 스킬에는 여러 프로젝트에서 재사용할 실행 지침을 둔다. 이 작업의 계획과 진행 이력은 여기서 관리한다.

첫 실험은 원래 `tests/toolkit/writing-for-humans/`에 있었지만, 문서 작성 스킬의 책임보다 넓은 평가 절차이므로 `tests/knowledge/document-ac/`로 옮겼다. 과거 실행 기록에 남은 옛 경로는 당시 관측의 일부로 보존한다.
