# 4단계: 개발 흐름과 자동 연결

검증된 양방향 변경 흐름을 사용자 요청·개발 이벤트·정기 검사에 연결하고, 사람에게 실제 결정이 필요한 예외만 전달한다.

[전체 로드맵](../roadmap.md) · 단계 상태: 미착수

## 진입 조건

3단계 양방향 반영·구현 검증 흐름이 검증돼야 한다. 대상 저장소·실행 계기·접근 권한·원격 반영 정책을 명시한다.

## 세부 조건

| ID | 항목 | 확인할 결과 |
|---|---|---|
| S4-01 | 실행 계기 | 사용자 요청·문서 변경·코드 PR·병합·정기 검사 중 지원 계기를 정의하고 입력 버전을 고정한다. 작성·리뷰·구현·검증의 필요한 경로를 선택한다. 초안과 반영 완료 상태를 구분한다. |
| S4-02 | 순서와 중복 | 이벤트 중복·지연·순서 역전·동시 실행을 처리한다. 같은 변경의 코드·문서 수정·PR 생성·게시 효과가 중복되지 않도록 한다. 자동 생성한 변경이 역방향 변경으로 다시 시작돼 무한 반복하지 않게 원인 실행을 연결한다. |
| S4-03 | 실패 운영 | 모델·네트워크·권한·외부 서비스 실패를 분류하고 재시도 가능 여부·중단 기준·재개 위치를 기록한다. 문서 반영 성공과 코드 구현·검증 성공을 따로 추적하고 성공하지 않은 단계나 외부 반영을 완료로 표시하지 않는다. |
| S4-04 | 사람 개입 | 자동 수정과 정책 결정을 구분한다. 필요한 질문에는 충돌 근거·영향·선택지를 포함하고 응답 후 해당 실행을 이어간다. 사용자 승인 경계를 이벤트 설정으로 우회하지 않는다. |
| S4-05 | 오래된 지식 검사 | 정기 검사로 누락된 이벤트, 기준 불일치, 원본 소실과 구현 대기 목표를 발견한다. 승인된 미구현 목표는 오래된 문서로 오판해 되돌리지 않는다. 미변경 상태는 불필요하게 재작성하거나 알리지 않는다. |
| S4-06 | 운영 관측 | 실행 시간·모델 호출·재시도·사용자 개입 사유를 측정한다. 성공·실패·대기 상태와 실제 산출물을 연결하고 운영자가 실행을 중단·재개할 수 있어야 한다. |

## 필수 판정 시나리오

허용된 시험 환경에서 이벤트 중복·유실·역순, 서비스 중단, 권한 만료, 사용자 정책 대기, 문서 수정이 코드 수정을 유발한 뒤 발생하는 역방향 이벤트를 주입한다. 양방향 자동 반영이 반복 고리에 빠지지 않는지 확인한다. 정상 변경은 초안 검토를 반복 요청하지 않고 끝나며, 승인 없는 원격 쓰기는 발생하지 않아야 한다.

## 완료 조건과 증거

모든 S4 조건을 지원 이벤트별로 검증한다. 자동 종료와 사용자 대기를 구분하고, 반복 운영에서 개입 이유와 복구 결과가 남아야 한다. 한 번의 수동 CLI 성공은 자동 운영 증거가 아니다. 검증 자료는 [공통 판정 규칙](../roadmap.md#완료를-판정하는-방법)을 따른다. 이 조건들은 구현 목표이며 현재 통과 주장으로 읽지 않는다.

## 현재 증거와 남은 일

미착수. 현재 실행은 에이전트가 CLI와 리뷰 전달을 조정하며 이벤트 실행·정기 운영·게시 시스템은 없다.

## 착수 시 적용할 설계 노트

- CLI의 기계용 오류 코드로 실패를 구분하되, 코드만으로 자동 재시도하지 않는다. 명령별 부작용·재개 조건·승인 범위에 따라 재시도 정책을 정하고, 반영 후 응답 유실 사례를 검증한다.
- 이벤트 식별자, 처리 요청 식별자, 원인 실행을 연결한다. 같은 이벤트의 재전달과 같은 내용의 새 사용자 요청을 구분한다. 자동 문서 수정 → 코드 수정 → 후속 이벤트가 원래 실행으로 돌아오는 사례에서 중복 효과와 반복 고리를 검사한다.
- 외부 요청의 성공 여부를 모르면 실패로 단정해 다시 보내지 않는다. 외부 반영 결과의 조회·대조와 재개 지점을 정한다. CLI 응답 버전과 도구 실행본 식별자를 운영 기록에 포함한다.
- 현재 SQLite의 프로젝트별 쓰기 직렬화가 다른 프로젝트나 임의 편집자의 문서 변경까지 조율하지는 않는다. 같은 대상을 여러 실행이 변경할 때 소유권·버전 검사·경쟁 처리 범위를 먼저 확정한다.

이벤트 버스나 상시 프로세스의 도입은 실제 실행 계기와 운영 요구를 확인한 뒤 결정한다. 이 노트 자체는 자동 운영 구현의 증거가 아니다.
