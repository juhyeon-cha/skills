# 문서 검색 고정 평가

이 파일과 corpus.json을 M0 실행 전에 고정한다. 대상은 로컬 예제 producer/consumer이며 운영 계약을 설명하지 않는다. 각 문서에 반복 배경 문단 80개를 붙여 긴 문서의 근거 위치를 평가한다. 문서 내용과 질문은 구현 결과를 보고 바꾸지 않는다.

| 질문 / 질의 | 정답 근거 |
|---|---|
| Q1 금액 필드 이름과 단위는? / `금액 단위` | producer contract.md 금액: total, KRW 정수 |
| Q2 계약 변경 시 소비자는 무엇을 변경하나? / `변경 total` | consumer guide.md 변경 영향: amount 읽기를 total로 변경 |
| Q3 어떤 검사가 운영 배포를 보장하나? / `운영 배포` | consumer guide.md 검증: 로컬 계약 검사, 운영 배포 미검증 |
| Q4 재시도 상한은? / `재시도 상한` | producer contract.md 두 번째 정책 절: 최대 3회; 첫 정책 절의 보관 30일과 혼동 금지 |
| Q5 JSON 예제의 필드와 값은? / `total 120` | producer contract.md 예제의 fenced JSON |
| Q6 숨겨진 저장소나 오래된 본문에서 답할 수 있나? / 위 질의 반복 | 권한 회수·부분 완료·철회·본문 drift에서는 본문 검색 0, 전체 미완료 유지 |
| Q7 커밋 메타데이터가 본문 검색으로 나오나? / `METADATA_ONLY_771` | 결과 0 |
| Q8 없는 기능을 추측하나? / `양자결제` | 결과 0, 부재를 전체 시스템에 대한 부재로 단정하지 않음 |

검색 계약: Unicode NFKC/casefold 후 공백 구분 단어 모두가 한 절의 제목·본문(문서 제목 포함)에 있어야 한다. 문서 경로·저장소 ID·해시 등 메타데이터는 검색 대상에서 제외한다. 본문 없는 제목도 검색 가능하며 제목 없는 문서는 경로를 표시명으로만 쓴다. 링크 URL은 본문에서 제외하고 label/code/table 텍스트는 포함한다. 결과는 절별로 반환하고 경로/절 순서로 안정 정렬한다. 의미 기반 순위나 자연어 답변 생성을 주장하지 않는다.

빈 질의는 검색 안내와 결과 0, 불일치는 결과 0이다. 응답과 페이지는 같은 fresh read projection을 사용한다. 검색 상태는 완료·현재 구현·목표·검증·색인과 구분한다. 검색 결과는 해당 문서의 실제 anchor로 이동해야 한다. 동일 서버에서 권한 회수 후 요청은 예전 본문/제목/발췌를 노출하지 않아야 한다.

M0: 동일 corpus에서 기존 JSON 필터와 파서 절 추출을 비교. 고정 질문의 모든 기대 근거/중복 anchor 확인, 메타데이터 오탐 0, 숨긴 입력 결과 0. 10회 절 추출 최대 1000ms 이내. 넘으면 원인과 대안을 재판정한다.

최종: Q1–Q5 정확한 절 직접 링크 5/5, Q6–Q8 누출·오탐 0. 실제 독립 모델에게 질문과 실제 검색 응답/도착 본문만 제공하고 정답표는 숨긴다. 별도 평가자가 답/근거를 판정한다. 이전 방식은 저장소 카드만 반환하므로 정답 절 직접 링크 수를 비교한다. 사용자 시간 단축은 측정하지 않으므로 주장하지 않는다.

비용: 같은 fixture의 기존 overview 검색과 새 HTTP 검색을 순차 5회씩 관측해 개별 지연과 응답 bytes를 남긴다. 새 검색 최대 2000ms, 오류 0을 로컬 사용성 기준으로 삼는다. 실제 모델 호출 시작/종료와 추가 질문 횟수를 기록한다. 토큰/금액이 도구에서 제공되지 않으면 미측정으로 표기한다. 정확도·비공개 보장이 먼저이며 상대 속도 우월성을 요구하지 않는다. 중앙 DB/외부 엔진 도입은 이 한정 corpus 관측만으로 일반화하지 않는다.
