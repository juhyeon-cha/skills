# Explanation and visual-form observation

This is a bounded development example for the source-writing changes after
`b3b2d07`. Reuse only the frozen synthetic cancellation inputs in
`../reader-content/fixture/` and their hashes in `../reader-content/frozen.json`.
Preserve that earlier observation. Its code is static evidence and its P1/O1/D1
records are fictional policy/problem/decision material, not real customer data.

Freeze these composition criteria before authoring:

| ID | Required reader outcome | Authority and boundary |
|---|---|---|
| C1 | Understand the user situation and distinguish order cancellation from payment refund before reading implementation details | P1/O1; do not invent a full shipping, billing or operations workflow |
| C2 | Find different organizing perspectives for FE action/screen, BE caller/data, planning policy/operational boundaries and PO problem/choices | Existing role questions plus P1/O1/D1; known context must not disappear into a list of unknowns |
| C3 | Explain why a missing response does not establish failure, and how an ordinary cancellation differs from that boundary case | screen.py and P1; explain the mechanism without inventing a team's historical decision rationale |
| C4 | Use a compact decision representation and titled callouts when they serve those tasks, with meaningful linear reading order | Current wiki supports Markdown tables/lists/quotes, not diagram rendering or an author-defined card grid; source text presented as a rendered flowchart fails |
| C5 | Preserve all consequential conditions and limits while changing presentation | Existing twelve question expectations in ../reader-content/expectations.json; no metric, refund, deployment or approval fabrication |

The author receives the existing source and role questions, the candidate writing
guidance and the target medium. Request a human-readable Korean guide, an evidence
page and a static wiki manifest using supported heading links. The guide must stand
alone for its reading tasks; the evidence page is available for tracing provenance.
The writer does not receive this protocol or the old answer key.

Independent review compares the actual documents against C1-C5 and source. A fresh
document-only reader gets the guide and these four prompts without the source or
answer key: explain the problem and cancellation/refund boundary; compare normal
and missing-response paths with reasons; describe what the four roles need to do;
explain what the chosen visual forms help reveal and what remains uncertain.
Keep exact inputs and actual returns. Report this as a model reading observation,
not demonstrated human usability or superiority over the preceding version.

Render the same documents with the existing wiki builder and checker, without
external downloads. Inspect the actual browser output at wide and narrow widths
when browser control is available. HTML or hash checks alone do not establish visual
legibility. No renderer change, publication, project initialization or installed-copy
update is part of this authoring example.
