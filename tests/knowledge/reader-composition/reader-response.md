1. **해결할 문제와 취소·환불의 경계**  
   고객이 취소 요청 후 실제 주문 상태를 알기 어려운 문제를 해결하려 한다. 고객 두 명의 문의 제보가 있지만 규모와 개선 효과는 미확인이다. 취소는 본인의 결제 완료 주문을 `cancelled`로 바꾸는 것이고, 환불은 결제 금액을 돌려주는 별도 작업이다. 취소 성공은 환불 완료를 뜻하지 않으며 결제사 연동·실제 환불은 범위 밖이다.

2. **정상 응답과 응답 유실 시 행동**  
   200 응답을 받으면 ‘주문 취소 완료’를 표시하고 목록으로 이동하도록 안내한다. 응답이 없으면 ‘처리 결과 확인 필요’를 표시하고 주문을 재조회하도록 안내한다. 서버가 변경을 마친 뒤 응답만 사라졌을 수도 있어 성공·실패를 단정할 수 없기 때문이다. 자동 재취소는 약속하지 않는다.

3. **역할별 다음 할 일**
   - **FE:** 본인 주문·결제 완료·요청 진행 중 아님 조건을 버튼과 연결하고 진행 상태를 관리한다. 응답별 안내와 재조회 후 화면 흐름을 구현·검증한다.
   - **BE:** 소유권 → 이미 취소됨 → 취소 가능한 상태 검사 순서와 반환 계약을 보존한다. 실제 API·영속 저장소·운영 동시성 등 현재 메모리 구현을 넘어서는 보장을 확인해야 한다.
   - **기획:** 신규 취소, 서버 반복 요청, 출고 이후 요청, 응답 유실, 타인 주문을 각각 관찰 가능한 수용 조건으로 구분한다. 환불 인계 주체나 기한을 임의로 확정하지 않는다.
   - **PO:** 제한된 취소 상태 확인안과 환불 포함 대안을 판단한다. 지표의 분모·관측 기간·목표치를 정의하고 실제 근거를 확보하며, 환불 포함 시 정책·운영 주체·결제사 의존성을 해결한다.

4. **흐름도·카드의 역할과 남은 사항**  
   흐름도는 취소 가능한 화면에서 시작한 **요청 1회**에 대해 결과별 안내와 다음 행동을 설명한다. 카드는 **가상 확정 범위, 환불 제외 범위, 미정인 운영 인계**를 구분한다. 환불 시점·담당자, 재조회 API와 후속 화면, 지표 정의, 비용·일정·출시 승인은 미정 또는 근거가 없다. 실제 UI 차단, 통신 복구, 영속성, 운영 동시성, 배포와 효과는 검증되지 않았다. 독립 문서 검토·렌더링·실행 검증도 대기 중이다.

큰 혼동은 없었다. 다만 ‘취소 상태를 직접 확인하는 기능’이라는 제품 설명에 비해 재조회 연결이 아직 없으므로, 상태 확인 경험 전체가 구현됐다고 읽으면 안 된다. 정책 선택의 사업 이유나 비용 우위도 문서로 뒷받침되지 않는다.
