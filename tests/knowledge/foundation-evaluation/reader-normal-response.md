1. **q1 — ConnectionError가 계속 발생하는 경우**
   - 답: 최초 호출을 포함해 총 3회 호출하며, 세 번째 호출도 실패하면 그 오류를 호출자에게 전달한다.
   - 근거: A의 “ConnectionError가 발생하면 최초 호출을 포함해 최대 3회 호출한다.” 및 “세 번째 호출도 실패하면 해당 오류를 호출자에게 전달한다.”
   - 부족한 정보: 호출 간 대기 시간은 명시되어 있지 않다.

2. **q2 — ValueError와 실행·배포 확인 여부**
   - 답: ValueError는 재시도 없이 즉시 호출자에게 전달한다. 실제 서버 실행과 배포 상태는 확인되지 않았다.
   - 근거: A의 “ValueError는 재시도 없이 즉시 호출자에게 전달한다.” 및 “실제 서버 실행과 배포 상태는 확인하지 않았다.”
   - 부족한 정보: 실제 서버에서의 실행 결과와 배포 상태.

3. **q3 — 빈 목록과 권한 없는 요청의 처리**
   - 답: 빈 목록은 헤더만 있는 CSV를 반환해야 한다. 권한 없는 요청은 파일을 생성하지 않고 거절해야 한다. 두 조건은 각각 구현하고 검증해야 한다.
   - 근거: B의 “빈 목록을 내보내면 헤더만 있는 CSV를 반환해야 한다.”, “권한이 없으면 파일을 생성하지 않고 요청을 거절해야 한다.” 및 “구현자는 이 두 조건을 각각 구현·검증하고 결과를 이 명세 버전에 연결해야 한다.”
   - 부족한 정보: CSV 헤더의 구체적 내용과 요청 거절의 응답 형식.

4. **q4 — 현재 상태와 완료 판정**
   - 답: B는 구현 완료된 기능 설명이 아니라 구현 대기 중인 목표 명세다. 다음 작업은 두 조건을 각각 구현·검증하고 결과를 이 명세 버전에 연결하는 것이다. 문서 품질 통과만으로 구현 검증 완료나 배포 확인을 판정할 수 없다.
   - 근거: B의 “이 명세는 합성 승인 결정 decision-export-v1의 목표다.”, “구현 코드는 없으며 구현 대기 상태다.”, “구현자는 이 두 조건을 각각 구현·검증하고 결과를 이 명세 버전에 연결해야 한다.” 및 “문서 품질 통과, 구현 검증 완료, 배포 확인은 별도로 판정한다.”
   - 부족한 정보: 구현·검증 결과와 배포 확인 자료. 배포되었다고 판단할 근거는 없다.

5. **q5 — 표현 수정과 코드 작업**
   - 답: C는 동작 변경을 요구하지 않는다. 수정 전후 모두 ConnectionError에 대해 최초 호출 포함 최대 3회 호출하고, 세 번째 실패의 오류를 전달한다. ValueError는 재호출 없이 즉시 전달한다. 따라서 이 표현 수정 자체를 이유로 코드 변경이 필요하지는 않다.
   - 근거:
     - 횟수: 수정 전 “최초 호출을 포함해 최대 3회 호출한다.” / 수정 후 “최초 호출까지 합쳐 최대 3회다.”
     - 마지막 실패: 수정 전 “세 번째 호출도 실패하면 해당 오류를 호출자에게 전달한다.” / 수정 후 “세 번째도 실패하면 그 오류를 호출자에게 전달한다.”
     - 예외: 수정 전 “ValueError는 재시도 없이 즉시 호출자에게 전달한다.” / 수정 후 “ValueError는 다시 호출하지 않고 즉시 호출자에게 전달한다.”
     - 변경 성격: “이 변경은 합성 예제 retry-v1의 같은 규칙을 다른 문장으로 설명한다.”
   - 부족한 정보: 실제 서버 실행과 배포 상태. C도 “실제 서버 실행과 배포 상태는 확인하지 않았다.”고 명시하므로, 이 비교로 실제 환경의 동작까지 검증할 수는 없다.
