# 1단계 문서 평가 사례

현재 코드 설명, 코드 없는 목표 명세, 표현만 수정한 문서를 같은 AC 계약으로 평가했다. 이 디렉터리는 합성 사례의 관측 원본이며 일반 문서의 정확성을 보장하지 않는다.

- `expectations.json`·`sources.json`: 독자 호출 전에 고정한 필수 명제와 권위. 목표 결정은 합성 입력이며 실제 제품의 승인 기록이 아니다.
- `reader-*-prompt.txt`: 새 독자에게 전달한 전체 입력. 코드·정답·결함 이름·앞선 판정은 전달하지 않았다.
- `reader-*-response.md`: 실제 응답 원문. 정상 `/root/reader_normal`, 변형 `/root/reader_variant`는 `fork_turns:none`으로 호출했다.
- `judgment.md`: `/root/document_judge`의 실제 독립 내용 검토·판정 응답. 문서 누락과 독자의 올바른 정보 부족 응답을 구분한다.
- `frozen.json`·`check.py`: 입력 바이트·ID·근거 연결 형식 검사. 독립 판정자의 해시 재계산은 훅에 차단됐고, 부모가 실제 검사했다.

`python3 tests/knowledge/foundation-evaluation/check.py`는 형식만 재검사한다. 새로운 독자 관측을 얻으려면 각각의 prompt 전체만 새 에이전트에 전달하고 응답을 새 파일로 보존한다. 판정자에게 근거·기대 명제·prompt·실제 응답과 배포 `document-ac.md`를 전달한다. 예전 응답을 새로운 문서 버전의 관측으로 재사용하지 않는다.

이번 입력 분리는 프롬프트 수준이다. 독자는 도구를 쓰지 않았지만 도구 접근을 기술적으로 차단한 실험은 아니다. 모델 ID·비용·토큰은 관측하지 않았다. 사람의 이해도와 구현·배포는 미검증이다. 정상 5개 AC 통과, 변형의 CUR-2·TGT-2 실패, 변형 WRD-1 미실행을 별도로 보존한다. 예외 설명과 목표 상태를 복원한 정상본의 판정은 존재하지만, 변형 응답을 본 뒤 별도의 새 독자로 복구본을 다시 읽히지는 않았다. 반려→수정→재리뷰 실제 루프는 별도 설치 관측에서 수행했다.

보조 `/root/evaluation`의 파일 쓰기와 독자 spawn은 `GUARD-DENY: UNREACHED — child role is unidentified`로 차단됐다. 부모가 반환된 자료를 기록하고 독자를 직접 호출했다. 실패한 호출을 통과로 바꾸지 않았다.
