# 전체 교환 계약 독립 검토 범위

검토한 패킷: `9916bf1ac157095bd42412ed487c3e8978b478d60302577c2b038518b20f6aaa`.

두 저장소의 고정 app.py/check.py, 현재 guide.md 전체와 주장별 바인딩, 코드 변경에서 시작한 intake의 전체 입력·수용 조건, 필수 개별 검사와 교환 검사의 보존된 원본 실행 기록을 읽었다. 패킷·intake·검사 증거 객체·외부 실행 스크립트·소스·문서의 SHA-256을 확인했고 두 실제 저장소가 패킷의 커밋에서 깨끗한 상태임을 확인했다.

생산자는 {"total": 1}을 반환하고 소비자는 total의 값을 그대로 읽는다. 소비자 필드 누락 시 KeyError가 발생하며 기본값 또는 호환 변환은 없다. 세 필수 검사의 실행 기록은 모두 종료 코드 0이고 전후 소스가 같으며, 교환 검사는 두 실제 모듈을 로드하여 생산자의 출력을 소비자에게 전달한 결과가 1임을 단언한다. 두 문서는 고정 소스 버전과 현재 동작, 함께 수정해야 하는 교환 필드 경계, 배포 미검증 범위를 일치되게 설명한다. 따라서 이 고정된 로컬 두 저장소 목표의 구현·문서를 통과로 판정했다.

이 검토는 새 실행을 생성하거나 검사 결과를 합성하지 않았다. 보존된 실제 실행 기록을 소스 및 스크립트와 대조했다. 검토 대상은 이 두 소규모 로컬 저장소의 total 교환 계약이다. 플러그인 전체 정확성, 운영 배포, 네트워크 교환, provider 인증, 모델 호출의 암호학적 증명, host의 미선언 실행 환경 의존성은 검증하지 않았다. 원격 게시나 원본 코드·문서 변경은 수행하지 않았다.
