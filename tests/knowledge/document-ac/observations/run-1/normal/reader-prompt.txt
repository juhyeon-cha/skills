# AI 질문과 암호 확인

암호를 제출하면 보류한 질문을 실제 분석 요청으로 보낸다. 암호 확인 뒤 같은 질문을 다시 보내지 않는다. 이 문서는 고정 소스의 정적 분석이며 브라우저·SAP·서버 실행 결과가 아니다.

공통 정책은 이 문서에 정의한다. 역할별 작업은 [FE 안내](frontend.md), [기획 안내](planning.md), [UI/UX 안내](uiux.md)를 참조한다. 원본은 [근거 발췌](../sources.json)에 있다. 제공자는 질문을 처리할 대상으로 선택한 AI 실행 대상이다.

## 질문 제출

| 조건 | 현재 동작 |
|---|---|
| 공백을 제외하면 질문이 비거나, 응답 대기 중이거나, 진행 요청이 있음 | 추가 전송하지 않는다 |
| 목록에 있는 선택 제공자가 암호를 요구하고 현재 대화에서 확인되지 않음 | 질문을 보관하고 암호 입력창을 연다. 아직 분석 요청을 보내지 않으며 질문 초안을 지우지 않는다 |
| 제공자 선택이 없거나, 선택 제공자가 목록에 없거나, 암호가 불필요함 | 암호 입력창 없이 전송한다. 목록에 없는 제공자의 서버 인증 성공을 보장하는 것은 아니다 |
| 현재 대화에서 이미 확인된 제공자 | 암호 입력창 없이 전송하며 저장된 암호가 있으면 함께 보낸다 |

바로 전송하는 경우 초안을 지우고 `sendTurn`을 한 번 호출한다. 근거는 `trySend`, `decideSubmit`, `isAskable`이다. 질문에 탐색 문맥을 결합하는 구체 형식은 이 발췌에서 확인하지 않았다.

## 암호 제출과 취소

`submitPasswordModal`은 `sendTurn(question, provider, passwordDraft)`을 통해 보류한 질문을 `POST /api/chat`으로 보낸다. 별도 인증 요청을 끝내고 질문을 다시 보내는 절차가 아니다.

| 조건 | 현재 동작과 결과 |
|---|---|
| 보류 질문 또는 선택 제공자가 없거나, 암호 확인 중이거나, 진행 요청이 있음 | 암호 제출을 무시한다 |
| 제출 가능 | 확인 중 상태를 켜고 입력창을 닫은 뒤 실제 질문 요청을 보낸다 |
| 최종 상태가 `401` 또는 `403` | 오류를 설정하고 해당 턴을 제거하며 암호 입력창을 다시 연다. 보류 질문·질문 초안·암호 입력은 남는다. 재입력 또는 취소할 수 있다 |
| 최종 상태가 `200` | 현재 대화에서 해당 제공자의 확인 상태와 암호를 기억한다. 이미 받은 응답을 사용하므로 질문을 추가 전송하지 않는다. 보류 질문·임시 암호·오류·질문 초안을 비운다 |
| 최종 상태가 `401`·`403`·`200` 이외임 | 제공자 확인 상태를 새로 추가하지 않는다. 암호 입력창을 다시 열지 않고 보류 질문·임시 암호·오류·질문 초안을 비운다. `sendTurn`이 처리한 실패 결과는 남는다. `500`, `499`, `502`도 여기에 해당한다 |
| 요청을 보내기 전 암호 입력창을 취소함 | `cancelPasswordModal`이 입력창을 닫고 보류 질문 참조·임시 암호·오류를 비운다. 질문 초안은 지우지 않는다 |

코드 주석의 “모든 non-200은 입력창과 보류 질문을 유지한다”는 설명과 달리, 실행 분기에서는 `401`·`403`만 입력창을 다시 연다. 이 문서는 실행 분기를 기준으로 한다. 그 밖의 실패에서도 입력을 유지하도록 바꾸는 것은 별도 정책 변경이다. 왜 이렇게 결정했는지는 제공된 근거만으로 알 수 없다.

## 연결 성공과 최종 결과

서버가 이벤트를 연속으로 보내는 응답 방식인 SSE에서는 연결이 HTTP `200`으로 열려도 분석은 나중에 실패할 수 있다. `postChat`은 `turn-error` 이벤트를 받으면 최종 상태를 `502`, `turn-cancelled`를 받으면 `499`로 바꾼다. 따라서 연결 시작의 `200`을 암호 확인 성공으로 기억해서는 안 된다.

같은 대화에서 암호 제출 요청이 `turn-error`로 끝나면 제공자 확인 상태를 새로 추가하지 않고 질문 초안을 비운다. 스트림 예외도 진행 요청이 중단됐거나 더 이상 현재 요청이 아니면 `499`, 그 밖에는 `502`를 반환한다. 스트림 옵션이 없는 호출은 예외를 다시 던지므로 이 상태 변환을 모든 호출에 확대하지 않는다. 여기서 `sendTurn`은 스트림 옵션을 전달한다.

진행 이벤트는 완료 증거가 아니다. `sendTurn`은 응답에 완료 탐색 정보가 없고 이전 진행 정보만 있으면 중단 상태를 반영한다. 스트림 판독 내부, 실제 오류 문구의 화면 표시, 서버의 중복 제거와 서버 작업 자체의 취소 보장은 이 발췌에서 확인되지 않았다.

## 새 대화

`startNewChat`은 진행 요청에 중단을 요청하고, 활성 요청·질문 초안·대화 기록과 세션 관련 상태를 초기화한다. 제공자 확인 목록과 기억한 암호도 비우며 암호 입력창을 닫는다. 선택한 제공자와 조회한 제공자 목록은 유지된다. 새 대화의 다음 질문에서는 암호 요구 조건을 다시 판단한다.

대화 전환 전후를 구별하는 세대 값을 증가시키므로, 이전 요청이 뒤늦게 반환돼도 `sendTurn`과 `submitPasswordModal`의 세대 검사 뒤에 있는 완료·세션·턴·암호 확인 후처리를 새 대화에 적용하지 않는다. 외부 서버 작업까지 중단됐다는 보장은 아니다.
