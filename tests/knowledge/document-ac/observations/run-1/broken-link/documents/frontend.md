# FE 구현 안내

암호 확인 성공 콜백에서 질문을 다시 보내면 중복 요청이 생긴다. 요청은 [공통 정책](policy.md)의 단일 전송 흐름에 연결하고, 최초 HTTP 성공과 최종 분석 결과를 구분한다.

| 구현 과제 | 확인할 곳과 결과 |
|---|---|
| 제출 연결 | `trySend`와 `decideSubmit`의 진입 조건을 유지한다. 공백·응답 대기·진행 요청 상태에서 추가 요청이 생기지 않아야 한다 |
| 암호 입력창 연결 | `submitPasswordModal`의 요청이 실제 질문 요청이다. 성공 후 별도 전송을 추가하지 않는다 |
| 실패 처리 | [암호 제출과 취소](policy.md#암호-제출과-취소)의 인증 거절과 기타 실패를 구분한다. 모든 실패에 초안 보존을 가정하지 않는다 |
| 진행 표시 | [연결 성공과 최종 결과](policy.md#연결-성공과-최종-결과)에 따라 스트림 연결·진행·완료·중단을 구분한다 |
| 새 대화 | [새 대화](policy.md#새-대화)의 초기화와 세대 검사를 함께 유지한다. 늦은 응답이 새 대화의 확인 상태를 되살리지 않아야 한다 |

실제 화면 검증에서는 버튼과 키보드 반복 제출의 요청 횟수, 인증 거절 후 재입력·취소, 비인증 실패, 연결 중단, 요청 도중 새 대화 전환을 확인한다. 이는 수행할 검증 과제이며 이 문서에서 브라우저 테스트를 실행한 것은 아니다. 화면 문구와 포커스 이동은 [UI/UX 안내](uiux.md)를 참조한다.
