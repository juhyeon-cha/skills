# UI/UX 검토 안내

사용자가 질문이 이미 전송됐는지, 진행 중인지, 다시 입력해야 하는지를 구분하도록 화면을 검토한다. 확인된 동작은 [공통 정책](policy.md)에 있으며 아래는 디자인 검토 과제다.

| 상황 | 검토할 안내와 복귀 |
|---|---|
| 암호 입력창 진입 | 암호 제출이 보류 질문 전송을 포함한다는 점을 알린다 |
| 제출 후 입력창 닫힘 | 닫혔다는 사실을 확인 성공으로 표시하지 않고 요청 진행을 알린다 |
| 인증 거절 후 재진입 | 오류, 재입력, 취소 경로와 유지되는 질문을 함께 확인한다 |
| 기타 실패·연결 중단 | 실패 결과를 정상 답변과 구분하고 현재 입력 정리를 고려해 다음 행동을 안내한다 |
| 새 대화 | 선택 제공자가 유지돼도 암호 확인이 다시 필요할 수 있음을 설명한다 |

키보드 포커스의 진입·재진입·취소 후 복귀, 오류와 진행 상태의 보조 기술 전달을 실제 화면에서 확인할 과제로 남긴다. 암호 입력창 취소와 진행 중 분석 중지는 별도 조작이며, 서버 작업 중단까지 보장하는 표현은 피한다.

현재 화면 디자인, 접근성 구현, 사용자 이해도는 이 발췌로 확인하지 않았다. 제안의 효과를 이미 측정한 것으로 설명하지 않는다. 상태 변경이 필요한 경우 [기획 안내](planning.md)와 [FE 안내](frontend.md)를 함께 사용한다.
