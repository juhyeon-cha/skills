# 서비스 기획 안내

인증 거절과 분석 실패는 현재 서로 다른 복구 흐름이다. [공통 정책](policy.md)의 조건·행동·결과를 현행 동작으로 읽고, 바꾸려는 동작은 변경안으로 구분한다.

| 검토 과제 | 판단할 내용 |
|---|---|
| 암호 확인의 의미 | 암호 제출은 질문을 함께 보내는 행동이다. 암호만 검사하는 것으로 요구사항이나 안내를 쓰지 않는다 |
| 실패 복구 | 인증 거절과 기타 실패의 입력 정리 차이를 인수한다. 기타 실패에서도 질문을 보존할지는 변경 요청이 있을 때 결정한다 |
| 알 수 없는 제공자 | 클라이언트가 입력창 없이 보낸다고 서버가 인증을 승인한 것으로 해석하지 않는다 |
| 새 대화 | 제공자 선택 유지와 암호 확인 초기화는 다른 상태다. 사용자 안내에서도 구분한다 |

인수할 때는 [공통 정책의 분기](policy.md#암호-제출과-취소)마다 이후 질문·암호 입력·대화 결과 상태를 비교한다. 진행 중 새 대화와 늦은 응답도 포함한다. 검토를 위해 새 정책을 반드시 결정할 필요는 없으며, 현재 동작의 기술과 실제 정책 변경을 구분한다.

정책 결정 배경, 실제 사용자 불편, 운영 수치와 일정은 근거가 없다. 정적 소스 설명을 사용자 조사나 실환경 검증 결과로 주장하지 않는다.
