# Changelog

## 0.1.2 — 2026-09-27

**폭 판단 — 사용자 명시 요청에 따른 패치 릴리스.** 새 notebook 명령은 일반 규칙상 minor 대상이지만 요청한 0.1.2로 발행한다. 기존 저장소·입력은 그대로 지원하며 데이터 마이그레이션은 없다. 새 v2 기록을 쓰기 전에는 해당 저장소의 모든 reader를 업데이트해야 한다.

- 기술 객체나 관측 근거 없이 개인 업무 용어·정의·별칭·예외를 기록한다. 원문·AI 요약·출처·범위·개정·적용 기간을 분리하고 정정 전 이력을 보존한다.
- `notebook capabilities`, `define`, `retrieve`로 자연어와 명시적 사용자·출처·업무 범위를 받는다. 안정적 ID·개정·일치 이유·근거 상태를 반환하고 충돌·모호함·오래된 근거·검색 실패를 구분한다. 개인 주장과 독립 검토는 조직 승인이 아니다.
- 동일한 완전 근거의 재관측은 기존 설명과 검토를 유지하면서 최신 관측 시각을 보존한다. `notebook inspect`는 저장 위치·소유 범위·이력·근거 상태를 읽기 전용으로 진단한다.
- 최신 부정 검토가 과거 통과 판정을 차단한다. 부분 검토의 실패는 전체 완료도 막으며, 검토 v2의 `review_id`는 새 판단과 재시도를 구분한다. 과거 요청 재전송은 최신 상태를 바꾸지 않는다.
- 최초 디렉터리형 DB 생성 실패의 재시도와 위키의 개인 정의·범위·개정 보존을 개선했다. 새 디렉터리형 DB 생성은 로컬 파일시스템 hard link를 요구한다. 자동화 초기화 중단의 진단·원본 보존 절차를 제공한다.
- 기존 기록·호스트 테이블을 변경하지 않는다. 구버전 reader는 개인 note v2와 review v2를 거부하므로 모든 reader를 먼저 업데이트하거나 별도 notebook을 사용한다. 공개 계약과 호환성은 `references/personal-knowledge.md`, 검토 사건은 `references/notebook.md`에 있다.
- 관련 로컬 테스트 107개와 PR CI 5개를 통과했다. 합성 검증은 실제 업무 데이터 정확성·모델 판단·호스트 연동·전원 장애·대규모 복원 성능을 보증하지 않는다. 소스·태그·GitHub Release 발행이며 설치 캐시와 실행 중인 세션을 자동 교체하지 않는다.

## 0.1.1 — 2026-09-24

**폭 판단 — 사용자 명시 요청에 따른 패치 릴리스.** 저장 설정과 백업·복원 명령이 추가되지만 기존 설치·디렉터리 저장소는 변경 없이 동작하며, 이번 배포는 요청한 0.1.1로 발행한다.

- 제품별 경로나 그래프 구조에 의존하지 않고 SQLite·산출물·개인 메모·위키 경로를 지정한다. 새 DB 생성과 기존 DB에 지식 전용 테이블 추가를 명시적으로 구분한다.
- `knowledge_*` 테이블과 자체 스키마 버전만 관리하며, 기존 애플리케이션 테이블과 DB 전체 버전·저널 모드를 보존한다. notebook별 출처·독자·참조를 분리하고 사용자용·개발자용 DB를 별도 파일로 둘 수 있다.
- 기존 디렉터리 저장소를 그대로 사용하면서, 원본을 변경하지 않는 이력 백업·복원을 제공한다. 복원 대상은 DB 관리 메모를 사용하는 notebook이며 근거·설명·검토·메모의 식별자와 이력을 보존한다.
- 초기화 커밋 잠금과 메모 소유 파일 생성 실패 후 재시도 경로를 검증했다. 설정 및 복구 절차는 `references/notebook-storage.md`에 있다.
- 저장·관측·위키 회귀 37개, CLI·기존 프로젝트 계약 69개와 저장소 게이트를 통과했다. 실제 제품 앱·운영 DB 연동과 대규모 처리·전원 장애는 이 릴리스 검증에 포함되지 않는다.

## 0.1.0 — 2026-09-24

**폭 판단 — 최초 릴리즈, 현재 버전 0.1.0 유지 (사용자 명시 요청).** 이전 knowledge 태그가 없어 첫 커밋부터 변경을 확인했다. toolkit에서 축적한 지식 기능을 독립 플러그인으로 제공한다.

### 근거를 연결한 지식 작성과 누적

- 최초 구성·변경 반영·독립 검토·조회·위키·운영의 여섯 스킬로 작업을 구분한다. 코드·목표·문서의 근거와 검토 상태를 연결하고 기존 프로젝트 상태의 호환성을 보존한다.
- FE·BE·기획·PO의 질문과 읽은 뒤 할 일을 기준으로 답·조건·이유·정상 및 경계 사례를 작성한다. 작성에는 toolkit의 `writing-for-humans`를 별도로 사용한다.
- 제품 공통 관측 노트북에 근거·설명·개인 메모를 누적한다. 출처와 독자를 분리하고 변경된 근거에 의존하는 설명과 이전·최신 자료를 작성 인계에 포함한다.
- 사용자 위키는 기존 vault 자료와 함께 관리할 수 있다. 개발자와 사용자의 지식을 분리하며 SAP 수집·해석·앱 연결은 SAP Harness가 담당한다.

### 조회·위키·운영

- 에이전트와 브라우저가 동일한 근거·상태를 조회한다. 허용된 문서 구간 검색, 관리 문서 페이지, 안전한 이동 경로와 진단·다음 행동 안내를 제공한다.
- 흐름도·카드를 Markdown에서 렌더링하고 읽기 화면·검색에 연결한다. 미검토 또는 근거가 바뀐 설명은 게시하지 않으며 실패 시 마지막 성공 위키를 보존한다.
- 복수 저장소의 목표·구현·부분 상태를 조회하고 로컬 자동화의 상태·재개·중단을 관리한다. 수집 성공은 설명 작성·독립 검토의 성공을 대신하지 않는다.

### 시작과 기존 사용자의 전환

- `knowledge:bootstrap`에서 Python·프로젝트·작성자·독립 검토 역량을 확인한다. Git 근거 흐름은 `scripts/requirements.txt`의 의존성을, 위키는 Node·MarkdownIt 실행 환경을 별도로 준비한다.
- toolkit의 이전 지식 스킬 사용자와 직접 실행 경로는 `references/transition.md`에 따라 전환한다. 저장된 자료·개인 메모를 삭제하거나 일괄 이관하지 않는다.
- 이번 릴리즈는 마켓플레이스 소스·태그·GitHub Release 발행이다. 실행 중인 세션이나 설치된 앱을 자동 교체하지 않는다.
