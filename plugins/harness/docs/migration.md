# Upgrade, resume and rollback

Use this procedure when switching artifacts or moving repository preparation from an EnterWorktree hook into `.harness.json`. An artifact update and a repository migration are separate changes. The installer never rewrites the repository config, credentials or work ledger.

## Before switching

1. Record the selected runtime, exact installed root, plugin version and content hash with the static distribution/doctor commands in [installation.md](installation.md). Keep the previous immutable artifact and its matching role registration receipt accessible. Equal version numbers do not mean equal source; the plugin release version, config `schema_version`, state path `v1`, role receipt version and doctor challenge are different contracts.
2. Record the repository revision and local changes, actual Git workspace identity, existing preparation configuration and any independent repository EnterWorktree registration. Preserve the prior config/hook revision and uncommitted work. Inspect an existing workspace instead of creating another directory or changing its name. Main and external linked paths follow the same Git identity contract in [workspace.md](workspace.md).
3. Retain the actual hook data directory and runtime/session metadata from SessionStart. Keep existing state and legacy override files in place. Store local backups privately when needed; avoid logging config extensions or credential contents. Pause conflicting preparation/state writers before any manual recovery or rollback.

## Switch the artifact and repository contract

1. Follow the selected runtime's install/update branch in [installation.md](installation.md). For Codex, generate roles into a separate staged directory and save the matching receipt. Verify the previous registered files against their prior receipt before replacing owned projections. Preserve foreign or modified files and resolve conflicts explicitly; `register` refuses to overwrite them. Activate one registration scope and one discovery path per skill/role. A staged duplicate directory must remain outside active discovery.
2. Keep `.harness.json` as the repository's single configuration source. An absent schema version and valid legacy coordinates remain supported; strings keep Bash semantics. Explicit schema 1 requires integer GitHub project coordinates. Use native executable argv when choosing structured commands, following [config-process.md](config-process.md). These formats do not convert automatically during plugin installation.
3. For a repository-owned preparation hook, first make required preparation failures return nonzero. Move that command and explicitly declared inputs into `.harness.json.bootstrap`/`preparation` and remove its independent EnterWorktree execution in the same repository cutover. Use only a registered common transport. Leaving the old executable hook registered produces `LEGACY_HOOK_UNVERIFIED`, even when an old marker or a bootstrap exists. Keep unrelated hook behavior by narrowing its matcher. A repository needing no preparation uses the documented no-command contract.
4. From the existing linked workspace, run common `enter`, then `ready`. Proceed with implementation only when `ready` returns 0 and `canDelegate: true`. Failure preserves the workspace; diagnose and retry preparation, not workspace recreation. Config/input changes invalidate readiness. A legacy marker cannot substitute for a successful receipt; the two runtimes share one preparation owner.
5. Start a new runtime session and verify static, loaded and live observations separately. Rebind an existing ledger actor with the new session ID and the actual hook data directory using [state.md](state.md). A successful claim and a failed state bind are separate facts; resolve bind without claiming again. Resume ordinary workflow using its call inventory and actual native outcomes, as [transcripts.md](transcripts.md) specifies. A previous child outcome cannot certify a fresh review.

Completion requires a matching artifact/role registration, repository readiness, current-session evidence for the intended runtime scope and readable ledger state. An installation list, old doctor PASS or preserved state file establishes none of the missing observations. Historical isolated Codex probes certify only their captured source/hash/session and capabilities; they do not certify the newly selected source or an ordinary task's completion. Claude live activation remains a separate prerequisite tracked in skills#268.

## Roll back without discarding work

1. Stop new delegations and identify active preparation workers and descendants. Wait for completion or use the documented recovery contract; never remove a lock based only on age. Preserve the worktree, dirty files, ledger claims and observed results. Rollback does not close tasks or release claims.
2. Select the previous artifact and its matching owned role projections/receipt together. Verify hashes and registration before starting a fresh session. Preserve modified/foreign projections for conflict resolution; remove an active duplicate registration only through the runtime's supported procedure. A receipt from another root/version/hash or an expired doctor challenge is not reusable load evidence.
3. If repository preparation was migrated, restore the corresponding prior config/hook revision as a reviewed repository change. Preserve unrelated local modifications. Avoid running the new common preparation while the restored independent legacy hook is active. The new reader deliberately reports that combination as unverified. Confirm the previous runtime's own readiness behavior rather than translating new ready receipts into old markers.
4. Keep new scoped state and untouched legacy files side by side. The released legacy runtime is not assumed to understand new `v1` state or scoped cancellation; its legacy files remain available, without automatic promotion of new observations into old formats. Returning to a compatible new artifact can reuse schema-compatible observations, but a new session still requires explicit actor binding and ordinary result validation. Never delete repository credential files, vault data or credential symlinks as an automatic rollback step.
5. Re-run static diagnostics, workspace inspection and the applicable runtime checks. Report any unavailable loaded/live evidence as UNREACHED. Changing the artifact does not upgrade or downgrade `.harness.json` or the ledger automatically.

## Compatibility limits

The minimum common runtime is Node 22; existing Bash/jq and backend prerequisites remain. Legacy strings require Bash. Windows `.cmd`/`.bat` use an explicit constrained argument adapter; native configured preparation uses a Windows 10 / Server 2016+ Job supervisor requiring Windows PowerShell 5.1 with Add-Type permitted. Missing native execution evidence remains UNREACHED. [Platform boundaries](platforms.md) distinguishes measured native core checks, unexecuted OS jobs and complete product support; WSL/Git Bash are transitional routes with separate evidence. Codex hook `cwd` may describe the session rather than an explicit command workdir, so successful hook diagnostics do not certify every relative shell write target.
